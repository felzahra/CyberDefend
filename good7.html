DPA Network Academy: Zero to Hero

A beginner-friendly journey through the Damietta Port Authority's Enterprise Network Architecture.

Level 1: Beginner

The Big Picture: What are we building?

Before we look at complex codes, let's understand what the Damietta Port Authority (DPA) network actually looks like. Imagine a massive office building. If every computer plugged into one giant switch, it would crash instantly. Instead, we use a 3-Layer Hierarchy.

🏢
The Building Analogy:
1. Core Layer (The Executive Floor): Fastest, most powerful switches. They connect to the internet and data centers. They don't deal with regular users.
2. Distribution Layer (The Department Managers): These sit between the Core and the Edge. They handle routing, security rules, and divide the network into subnets (VLANs).
3. Edge Layer (The Front Desk): These switches sit under desks and in server racks. This is where your PC, IP Phone, and Access Points plug in.
Figure 1: The DPA Network Core. High-speed switches kept in a secure, climate-controlled room.
Level 2: Intermediate

The Core Layer & VSX (The Bosses)

At the very top of DPA's network are two massive Aruba 8400 switches: DPA-Core-Primary and DPA-Core-Secondary. But what happens if the Primary switch catches fire? The whole network goes down. To prevent this, we use VSX (Virtual Switching Extension).

🤝
VSX Analogy: Imagine two CEOs sitting in the same office, sharing the same brain. If one has to leave, the other instantly takes over without anyone noticing. VSX makes two physical switches act as one logical switch.

The Magic of Virtual IPs (Active Gateway)

In a VSX pair, both switches have their own physical IP addresses (e.g., 10.0.2.2 and 10.0.2.3). However, they present a single Virtual IP (Active Gateway) to the rest of the network. If the primary switch fails, the secondary instantly assumes that Virtual IP. Endpoints never notice a disruption.

DPA-Core-Primary Configuration
# 1. The Inter-Switch Link (ISL): The massive cable connecting the two brains interface lag 128 no shutdown description ISL-link vlan trunk allowed all # Allows all traffic between switches # 2. The Keepalive Link: A backup heartbeat to ensure they are both alive interface 1/5/24 ip address 10.0.4.2/24 # 3. Enabling VSX vsx system-mac 02:01:00:00:00:01 # They share this MAC address! inter-switch-link lag 128 role primary keepalive peer 10.0.4.3 source 10.0.4.2 # 4. Creating the Virtual IP (Active Gateway) interface vlan 2 ip address 10.0.2.2/24 # Physical IP of Core 1 active-gateway ip 10.0.2.1 # The shared Virtual IP! active-gateway ip mac 02:01:00:00:00:02
Hero Tip: Notice how the Primary switch has IP `10.0.2.2` but the Active Gateway is `10.0.2.1`. The Secondary switch has IP `10.0.2.3` but also points its Active Gateway to `10.0.2.1`. If Core 1 dies, Core 2 instantly answers for `10.0.2.1`.
Level 3: Advanced

The Distribution Layer (The Managers)

Downstairs, we have the Distribution switches: ND4-prim and ND4-Secondary. These also run VSX to protect the network. But they have a very important job: Routing and Active Gateways.

When your laptop wants to send a message to the server, it needs to know "Who is the manager of my subnet?" That manager is the Active Gateway (Virtual IP).

ND4-prim Configuration
# Creating a subnet for the Hardware Lab (VLAN 140) interface vlan 140 ip address 10.0.140.2/24 # The physical IP of this switch # The Active Gateway: A fake virtual IP that floats between the two switches active-gateway ip 10.0.140.1 active-gateway ip mac 02:01:40:04:41:01 # Sending DHCP requests to the main server ip helper-address 10.0.10.12
🪄
Active Gateway Analogy: The two switches share a "Virtual IP" (`10.0.140.1`). Your PC only knows this Virtual IP. If ND4-prim reboots, ND4-Secondary instantly answers for that IP. To your PC, the network never blinked!

Routing (OSPF)

How does the Core know where VLAN 140 is? The Distribution switch tells it using a routing protocol called OSPF. It broadcasts its subnets to the rest of the network.

router ospf 1 redistribute connected # Tell everyone about my directly connected subnets area 0.0.0.0 # The backbone area
Level 4: Expert

The Edge Layer (The Front Desk)

At the very bottom are the Edge switches (e.g., ND4-E425). These connect to users. Because they sit under desks, they don't run complex VSX. Instead, they use LACP Trunks to connect back to the Distribution Managers.

ND4-E425 Configuration
# Group physical ports 9 and 10 into one super-cable called Trk1 trunk 9-10 trk1 lacp # Send all management traffic over this trunk using VLAN 244 vlan 244 name "Switch-Managment" untagged Trk1 ip address 10.0.244.35 255.255.255.0 exit # Set the default gateway to the Distribution Switch's Active Gateway ip default-gateway 10.0.244.1
Figure 2: LACP allows multiple physical cables to act as one, providing speed and redundancy.
Level 5: Hero

The Glue: How it all connects together

Now let's look at the "Glue" that holds these 3 layers together. How does a Core switch connect to a Distribution switch safely? They use MC-LAG (Multi-Chassis Link Aggregation).

🔌
MC-LAG Analogy: An Edge switch uses LACP to plug into ONE switch using two cables. But what if that ONE switch dies? MC-LAG allows an Edge switch to plug into TWO different Distribution switches at the same time, treating them as a single device.

Let's trace the path of a packet from the Core down to an Edge switch.

Core LAG Connects To Distribution LAG Native VLAN
LAG 244 (MC-LAG) ↔ LAG 244 (MC-LAG) VLAN 14 (OSPF-ND4)
LAG 128 (ISL) Core 1 ↔ Core 2 N/A VLAN 1 (All)
Dist LAG 1-47 ↔ Edge Trk1 VLAN 244 (Mgmt)
DPA-Core-Primary (Connecting down to ND4)
interface lag 244 multi-chassis vsx-sync vlans no shutdown description CORE-ND4 no routing vlan trunk native 14 vlan trunk allowed all lacp mode active

Because of `multi-chassis` and `vsx-sync`, the Core switches coordinate so that the Edge/Dist switch thinks it is plugged into a single, unbreakable switch.

Congratulations! You have gone from a beginner looking at a server room to understanding advanced ArubaOS-CX concepts: VSX, Active Gateways, OSPF, and MC-LAG. You are a Network Hero!

3. Routing & VLAN Gateways

Core switches run OSPF Process 1 (Area 0.0.0.0) and redistribute connected and static routes. The default route for the entire network points to the Firewall.

  • ip route 0.0.0.0/0 10.0.250.1 (Default route to PA/FortiGate perimeter).
  • Active Gateways (SVIs): Core provides Active Gateway IPs (Virtual IPs) for Server Farm and OSPF transit VLANs.
  • VLAN 2 (Mgmt): VIP 10.0.2.1 | VLAN 4 (VM Desktops): VIP 172.28.4.1 | VLAN 250 (PA FW): VIP 10.0.250.11
  • VLANs 11-18 are dedicated OSPF transit networks to Network Districts 1-8.

3. Routing, VLANs & DHCP Relay

Distribution switches run OSPF Process 1 (Area 0.0.0.0) to peer with the Core. They act as the Active Gateway (Virtual IP) for all user VLANs in District 4. The default route points to the Core's transit VLAN.

  • ip route 0.0.0.0/0 10.0.14.2 (Default route to Core Layer).
  • DHCP Relay: All user VLANs are configured with IP Helper addresses to forward DHCP requests: ip helper-address 10.0.10.12, 10.0.10.13, 10.0.10.14.
