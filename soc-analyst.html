🧠 Core SOC Analyst Concepts & Frameworks

A Security Operations Center (SOC) Analyst is the first line of defense. Mastering these frameworks and concepts is critical for triaging alerts, hunting threats, and understanding adversary behavior.

The Cyber Kill Chain

Developed by Lockheed Martin, it maps the stages of an attack: Reconnaissance, Weaponization, Delivery, Exploitation, Installation, Command & Control (C2), and Actions on Objectives. Helps analysts understand what phase an attack is in.

MITRE ATT&CK Framework

A globally accessible knowledge base of adversary tactics, techniques, and procedures (TTPs) based on real-world observations. Crucial for mapping alerts to known adversary behavior.

The Diamond Model

Establishes the fundamental aspects of an intrusion: Adversary, Infrastructure, Capability, and Victim. Used to group intrusions and understand the threat actor's intent.

CIA Triad

Confidentiality, Integrity, and Availability. The benchmark for evaluating information security. Every alert ultimately threatens one of these pillars.

SIEM (Security Info & Event Mgmt)

Platforms like Splunk, QRadar, or Microsoft Sentinel that aggregate log data, correlate events, and trigger alerts based on detection rules.

EDR / XDR

Endpoint Detection and Response (EDR) monitors endpoint activities (processes, registry, network). XDR extends this visibility across networks, cloud, and email.

Common Attack Vectors

  • Phishing: Deceptive emails aiming to steal credentials or drop malware. Look for anomalous User-Agents, login locations, and MFA fatigue.
  • Ransomware: Encrypts files and demands payment. Often preceded by lateral movement, volume shadow copy deletion (vssadmin delete shadows), and SMB brute-forcing.
  • Lateral Movement: Moving from one system to another. Look for Pass-the-Hash (PtH), Pass-the-Ticket (PtT), and abnormal RDP/WinRM usage.
  • Persistence: Techniques to maintain access (Scheduled tasks, Run keys, Web Shells, Startup folders).

🐧 Linux Services & Commands

Linux is the backbone of most enterprise servers. SOC analysts must know how to navigate the file system, parse logs, and hunt for persistence mechanisms via CLI.

Service & Process Management

# Check status of a service
systemctl status sshd

# List all running services
systemctl list-units --type=service --state=running

# View running processes (real-time)
top  # or 'htop' if installed

# Find a specific process by name (e.g., rogue reverse shell)
ps aux | grep "nc -e"

# Kill a process by PID
kill -9 1234

Hunting Persistence in Linux

# Check user crontabs for scheduled malicious scripts
crontab -l

# System-wide cron jobs
cat /etc/crontab
ls -la /etc/cron.*

# Check bash profile/profile for malicious aliases or paths
cat ~/.bash_profile
cat ~/.bashrc

# Hunt for SUID binaries (Privilege Escalation vectors)
find / -perm -4000 -type f 2>/dev/null

# Check authorized_keys for unauthorized SSH access
cat ~/.ssh/authorized_keys

Network & Connections

# Show all listening TCP/UDP ports and PID
ss -tulpn

# Show active established connections
ss -tunap | grep ESTAB

# Capture packets on eth0 and save to PCAP for Wireshark
tcpdump -i eth0 -w capture.pcap

🪟 Windows Services & Commands

Most enterprise endpoints run Windows. Attackers frequently target Windows services like SMB, RDP, and WinRM. Knowing CMD, PowerShell, and WMI is non-negotiable.

System & User Investigation (CMD)

# Get system information and OS version (check for missing patches)
systeminfo

# List all running services
sc query

# Check what time a user logged in
net user Administrator | findstr "Last logon"

# View active network connections and PIDs
netstat -ano

# View scheduled tasks (check for persistence)
schtasks /query /fo LIST /v

PowerShell for Threat Hunting

# Get all running processes with their paths (look for weird locations like C:\Temp)
Get-Process | Select-Object Name, Id, Path

# Check execution policy (attackers often lower this)
Get-ExecutionPolicy -List

# Query Windows Event Logs for Event ID 4625 (Failed Logon) - Brute Force detection
Get-EventLog -LogName Security -InstanceId 4625 -Newest 10

# Find files modified in the last 24 hours (useful for incident response)
Get-ChildItem -Path C:\ -Recurse -File | Where-Object { $_.LastWriteTime -gt (Get-Date).AddDays(-1) }

# Query WMI for startup commands (persistence)
Get-CimInstance Win32_StartupCommand | Select-Object Name, command, Location, User

📊 Key Log Locations & Event IDs

Knowing where to look is half the battle. Here are the critical log locations for incident response and threat hunting.

Windows Event Viewer (eventvwr.msc)

Critical Windows Security Event IDs

  • 4624: Successful Account Logon (Note Logon Type: 2=Interactive, 3=Network, 10=RemoteInteractive/RDP)
  • 4625: Failed Account Logon (Brute Force indicator)
  • 4634: Account Logoff
  • 4648: Explicit Credentials Logged (RunAs usage)
  • 4672: Admin privileges assigned to new logon
  • 4688: New Process Created (Command-line logging if enabled)
  • 4698: A scheduled task was created (Persistence)
  • 4720: User Account Created
  • 4732: Member added to Security-enabled Local Group
  • 1102: Security Audit Log Cleared (Huge red flag for anti-forensics)

Linux & Network Log Locations

  • /var/log/auth.log (Debian/Ubuntu) or /var/log/secure (RHEL/CentOS): SSH logins, sudo usage, user creation.
  • /var/log/syslog or /var/log/messages: General system activity, service starts/stops, hardware errors.
  • /var/log/apache2/access.log or /var/log/nginx/access.log: Web server requests (look for SQLi/XSS payloads).
  • ~/.bash_history: Command history for individual users (check if attackers tried to clear it).
  • /var/log/suricata/ or /var/log/zeek/: Network Security Monitoring (NSM) logs mapping IPs to protocols and files transferred.

SIEM Query Examples

SOC Analysts spend most of their time in a SIEM. Here are examples of what queries look like to find brute-force attacks.

# Splunk SPL: Find users with more than 10 failed logins in 5 minutes
index=windows EventCode=4625 
| stats count by src_ip, user 
| where count > 10 
| sort -count

# Microsoft Sentinel / Azure KQL: RDP connections from unknown IP locations
SecurityEvent 
| where EventID == 4624 and LogonType == 10 
| summarize count() by Account, IpAddress, Computer 
| where IpAddress !in ("10.0.0.0/8", "192.168.0.0/16")
Analyst Tip: Always verify the source of your logs. If a firewall isn't sending logs, the SIEM can't detect attacks coming through that firewall. "No logs" does not mean "no attack."
