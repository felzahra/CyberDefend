ND2-E204 — Access Switch ArubaOS-Switch (ProVision) · JL258A / Aruba 2540 · 10-Port

ℹ️
This is a layer-2 access switch running ArubaOS-Switch (formerly ProVision). It sits at the building floor level, connects end-user devices, and uplinks to the distribution core via a single LACP trunk. The model JL258A is an Aruba 2540-24G-PoE switch.

LACP Trunk to Distribution
LINK AGGREGATION
TRUNK
trunk 9-10 trk1 lacp
CommandWhat It Does
trunk 9-10 trk1 lacpBundles physical ports 9 and 10 into a single logical trunk called Trk1 using the LACP (802.3ad) protocol.

• 9-10 = port range (SFP uplink ports on the 2540)
• trk1 = the trunk group name (like Cisco's port-channel 1)
• lacp = enables LACP negotiation (active by default in ProVision)

This provides 2 Gbps bandwidth and redundancy — if one SFP link fails, traffic continues on the other. The other end (ND4-prim) has the matching MCLAG configuration.
💡
Cisco vs ArubaOS-Switch trunk:
• Cisco: interface range gi0/1-2 → channel-group 1 mode active
• ArubaOS-Switch: trunk 9-10 trk1 lacp (one line!)

Default Route
ROUTING
STATIC ROUTE
ip route 0.0.0.0 0.0.0.0 10.0.242.1
CommandWhat It Does
ip route 0.0.0.0 0.0.0.0 10.0.242.1Sets a default static route (gateway of last resort). All traffic not matching a more specific route is sent to 10.0.242.1.

This is the Distribution switch's SVI IP on VLAN 242 (Managment-Switch). The access switch uses this to reach the management network, NTP servers, syslog, etc.

• Syntax is identical to Cisco IOS
• The access switch needs this because it has an IP on VLAN 242 but doesn't run a routing protocol
⚠️
Why does an L2 switch need a route? ArubaOS-Switch (ProVision) supports basic layer-3 static routing even on "access" switches. This route is used for out-of-band management traffic originating from the switch itself (SNMP traps, syslog, NTP, firmware downloads).

VLAN 1 — Default VLAN

CommandExplanation
name "DEFAULT_VLAN"Assigns a human-readable name. VLAN 1 exists by default on all ArubaOS-Switch ports.
no untagged 1-8,Trk1Removes ports 1-8 and Trk1 from the untagged (access) membership of VLAN 1. By default, all ports are untagged in VLAN 1. This command "frees" those ports so they can be assigned to other VLANs. Without this, you can't make ports 1-8 untagged in VLAN 98.
ip address dhcp-bootpConfigures the VLAN 1 SVI to obtain its IP via DHCP or BOOTP. This is the switch's management IP if no other VLAN has a static IP. In this network, it's a fallback — the real management IP is on VLAN 242.
ipv6 enableEnables IPv6 processing on this VLAN interface.
ipv6 address dhcp fullObtains a full IPv6 address via DHCPv6 (not just SLAAC). The switch gets its IPv6 address, DNS, and other options from a DHCPv6 server.

VLAN 98 — Data VLAN (User Ports)

CommandExplanation
untagged 1-8Assigns ports 1 through 8 as untagged (access) members of VLAN 98. Devices plugged into these ports send/receive untagged Ethernet frames — the switch automatically adds/removes the VLAN 98 tag internally. This is equivalent to Cisco's switchport access vlan 98.
tagged Trk1Makes Trk1 a tagged member of VLAN 98. Frames going out Trk1 toward the distribution switch carry an 802.1Q tag with VLAN ID 98. This is how the distribution switch knows which VLAN the traffic belongs to. Equivalent to Cisco's switchport trunk allowed vlan add 98.
no ip addressExplicitly removes any IP address from the VLAN 98 SVI. This switch doesn't need to route for VLAN 98 — the distribution core handles inter-VLAN routing.

VLAN 242 — Switch Management

CommandExplanation
untagged Trk1Trk1 is an untagged member of VLAN 242. This means management traffic between this switch and the distribution core on VLAN 242 flows without 802.1Q tags on this trunk.

⚠ Important: In ArubaOS-Switch, a port can only be untagged in ONE VLAN. Since Trk1 is untagged in VLAN 242, all other VLANs (like 98) must be tagged on Trk1. VLAN 242 acts as the "native VLAN" for this trunk.
ip address 10.0.242.14 255.255.255.0Assigns 10.0.242.14/24 as the switch's management IP address. This is how network admins SSH, SNMP-poll, or web-manage this switch. The gateway is 10.0.242.1 (set in the default route above), which is the distribution switch's VLAN 242 SVI.
📌
Access Switch Port Map Summary:
• Ports 1-8: Access ports, untagged VLAN 98 (user data)
• Ports 9-10: SFP uplinks, bundled as Trk1 (LACP)
• Trk1 untagged: VLAN 242 (management/native)
• Trk1 tagged: VLAN 98 (data)

Spanning Tree Priority
LOOP PREVENTION
STP
spanning-tree Trk1 priority 4
CommandWhat It Does
spanning-tree Trk1 priority 4Sets the Spanning Tree port priority of Trk1 to 4 (default is 8). Lower value = higher priority = more likely to become the root port (the port that forwards traffic toward the root bridge).

Since this access switch has only one uplink (Trk1), this setting mainly matters if there were redundant uplinks — it ensures Trk1 is preferred over any other path. The priority value is multiplied by 4096 internally (4 × 4096 = 16384 in the actual BPDU).

HARDWARE / SECURITY
MISC

CommandWhat It Does
allow-unsupported-transceiverAllows the use of third-party / non-HPE SFP/SFP+ transceivers. By default, Aruba switches reject non-certified optics and show a warning. This command bypasses that check. Common when using cheaper or specialty optics (like long-range BiDi SFPs) that aren't on HPE's compatibility list.

⚠ Risk: Unsupported transceivers may cause intermittent issues and are not covered by HPE support.

• Operator — read-only access (like Cisco's enable level 1)
• Manager — full read-write access (like Cisco's enable level 15)

The actual password hash is not shown in display current-configuration for security — it's stored separately.

sflow collector 10.0.10.76Configures an sFlow collector at 10.0.10.76. sFlow (Sampled Flow) is a monitoring protocol that sends packet samples and interface counters to a collector for traffic analysis, bandwidth visualization, and anomaly detection. The collector is likely running software like InMon, PRTG, or a custom sFlow receiver.
sflow agent-ip 10.0.2.42Sets the source IP address used in sFlow packets sent to the collector. Uses 10.0.2.42 (the switch's VLAN 2 SVI IP) so the collector knows which switch the data came from.
ntp server 10.0.2.2Points to an NTP server at 10.0.2.2 for time synchronization. Accurate time is critical for log correlation, certificate validity, and sFlow timestamps.
ntp enableGlobally enables the NTP client on the switch.

ssh server vrf defaultEnables the SSH server on the default VRF (data plane). Allows SSH access from any network reachable via the routing table.
ssh server vrf mgmtEnables SSH on the management VRF (out-of-band network). Allows SSH access via the dedicated management port (10.0.3.42), keeping management traffic separate from data traffic for security.

Spanning Tree — RPVST
LOOP PREVENTION
STP
spanning-tree mode rpvst
spanning-tree
CommandExplanation
spanning-tree mode rpvstSets the spanning tree mode to RPVST (Rapid Per-VLAN Spanning Tree). This is the ArubaOS-CX equivalent of Cisco's spanning-tree mode rapid-pvst.

• Rapid = uses RSTP (802.1w) for fast convergence (sub-second instead of 50 seconds)
• Per-VLAN = each VLAN has its own spanning tree instance, allowing different root paths per VLAN for load balancing
• This is the recommended mode for modern campus networks
spanning-treeGlobally enables spanning tree on the switch. Without this line, STP is disabled even if the mode is configured.
💡
Why RPVST and not MSTP? RPVST gives per-VLAN load balancing (e.g., VLAN 124 roots through ND4-prim, VLAN 125 roots through ND4-sec). MSTP groups VLANs into instances. For this network with many department VLANs, RPVST provides maximum flexibility at the cost of slightly more BPDU traffic.

Out-of-Band Management Port
Oob MANAGEMENT
MGMT INTERFACE
interface mgmt
    no shutdown
    ip static 10.0.3.42/24
    default-gateway 10.0.3.41
CommandExplanation
interface mgmtEnters the configuration for the dedicated out-of-band management port. This is a physical RJ-45 port (separate from data ports) that exists solely for management traffic. It's in its own VRF (vrf mgmt), completely isolated from data plane traffic.
no shutdownEnables the interface (it's administratively down by default in AOS-CX).
ip static 10.0.3.42/24Assigns a static IP address to the management port. Subnet: 10.0.3.0/24. This IP is only reachable from the management network, not from user VLANs — providing a security air gap.
default-gateway 10.0.3.41Sets the default gateway for the management VRF. 10.0.3.41 is likely a management switch or firewall that provides access to the management network for SSH, firmware downloads, etc.
📌
Two management paths on this switch:
1. In-band: VLAN 2 SVI (10.0.2.42/24) — via data network
2. Out-of-band: Mgmt port (10.0.3.42/24) — via dedicated management network

If the data plane goes down, admins can still reach the switch via the OOB port. This is a critical best practice for core switches.

system interface-group <n> speed 10gCreates interface groups that set the maximum speed for a range of ports. On Aruba CX switches, some ports can run at 1G or 10G depending on the transceiver. Setting speed 10g tells the switch hardware to allow 10Gbps operation on these ports.

• Group 1: Ports 1/1/1 through 1/1/12 → 10G capable
• Group 2: Ports 1/1/13 through 1/1/24 → 10G capable
• Group 3: Ports 1/1/25 through 1/1/36 → 10G capable
• Group 4: Ports 1/1/37 through 1/1/48 → 10G capable

Without this, some ports may default to 1G max even with 10G SFP+ modules inserted.

    vlan trunk allowed all

! ... lag 2 through lag 47 are IDENTICAL ...

interface lag 47 multi-chassis
    vsx-sync vlans
    no shutdown
    no routing
    vlan trunk native 244
    vlan trunk allowed all
    lacp mode active
CommandExplanation
interface lag <n> multi-chassisCreates a Multi-Chassis LAG (MCLAG). Unlike a regular LAG that bundles ports on a single switch, an MCLAG spans two physical switches (ND4-prim + ND4-sec). The access switch sees both distribution switches as a single logical device. If one distribution switch fails, the access switch's LACP detects the failure and reroutes through the surviving switch — no STP reconvergence needed.
vsx-sync vlansSynchronizes this LAG's VLAN configuration to the VSX peer. Ensures both sides of the MCLAG have identical VLAN allowlists.
no shutdownAdministratively enables the LAG interface.
no routingDisables IP routing on this LAG — it's a pure layer-2 trunk. No IP packets are processed directly on this interface; routing happens on the SVIs.
vlan trunk native 244Sets VLAN 244 as the native (untagged) VLAN on this trunk. Frames on VLAN 244 are sent without 802.1Q tags. This is the management channel to access switches — matching the access switch config where VLAN 242/244 is untagged on the uplink.

⚠ Note: The native VLAN must match on BOTH ends. Mismatched native VLANs cause silent connectivity issues.
vlan trunk allowed allAllows all VLANs on this trunk. Every VLAN created on the switch (1, 2, 4, 14, 34, 44, 124-150, 200, 244, 999) can pass through this MCLAG. This simplifies config since all access switches potentially need all VLANs.
lacp mode activeEnables LACP in active mode. The switch actively sends LACPDU frames to negotiate the link aggregation. The access switch (ArubaOS-Switch) also uses LACP, so both sides actively negotiate. Active-active is the standard for Aruba MCLAGs.
🏗️
Why 47 MCLAGs? Each MCLAG connects to a different access switch. With 47 access switches in the building, each gets its own MCLAG for isolation and independent failover. One MCLAG failure doesn't affect others.
⚠️
Not all MCLAGs have physical ports assigned on this switch. Some MCLAGs (e.g., lag 2, 5, 22) have no lag <n> assignment under any physical interface on ND4-prim — those ports are on ND4-sec. The MCLAG config exists on both switches for VSX sync consistency, but only one side has the physical connections.

CommandExplanation
interface lag 128
(NOT multi-chassis)		The ISL (Inter-Switch Link) is a regular LAG, not an MCLAG. It only exists between the two VSX peers. It carries:
• VSX control traffic — heartbeat, state synchronization
• Data plane traffic — frames that need to cross from one peer to the other (e.g., if an access switch sends traffic to ND4-prim but the destination MAC is learned on ND4-sec)

Uses ports 1/1/55 and 1/1/56 (likely 10G SFP+).
vlan trunk native 1 tagSets native VLAN to 1 but with the tag keyword — meaning VLAN 1 frames are tagged (not untagged). This is Aruba's recommended best practice for ISL links to prevent VLAN 1 leakage and ensure all traffic on the ISL is explicitly tagged.
interface lag 244 multi-chassisThe uplink to the firewall/core router, configured as an MCLAG. Both ND4-prim and ND4-sec connect to the firewall via this MCLAG, providing redundant uplinks. Uses ports 1/1/53 and 1/1/54.
vlan trunk native 14VLAN 14 is the native VLAN on the uplink. This is the VLAN used to reach the firewall at 10.0.14.2 (the default route next-hop).

VSX Keepalive Link (Dedicated)
VSX HEARTBEAT
KEEPALIVE PORT
interface 1/1/48
    no shutdown
    description Keepalive-link
    ip address 10.0.4.41/24
CommandExplanation
interface 1/1/48A dedicated physical port (not part of any LAG) used exclusively for the VSX keepalive. This is a layer-3 routed port (has a direct IP address, no no routing command).
ip address 10.0.4.41/24IP address for keepalive messages. The peer (ND4-sec) uses 10.0.4.42 on its keepalive port. These IPs are referenced in the vsx configuration (see below). The keepalive uses a direct cable between the two switches — no switches in between.
⚠️
Why a separate keepalive link? The ISL (lag 128) carries VSX data + control, but if the ISL fails, the switches need an independent path to detect if the peer is truly down vs. just the ISL being down. The keepalive link provides this independent health check. Without it, a split-brain scenario could occur where both switches think they're the primary.

interface 1/1/1 ... lag 1Port naming: module/slot/port. 1/1/1 = module 1, slot 1, port 1. The lag 1 command assigns this physical port to LAG 1 (MCLAG). The port inherits all LAG settings (VLANs, LACP, etc.).
speed 1000-fullForces the port to 1000 Mbps full-duplex. Used when connecting to 1Gbps access switches or SFP modules. Some ports also have !actual speed auto 10g comments — meaning the port is set to 1G but the hardware negotiated 10G (likely due to a 10G SFP+ module being inserted despite the 1G config).
no shutdownEnables the port. In AOS-CX, all data ports are shutdown by default — you must explicitly enable each one. This is different from Cisco where ports are up by default.
no routing (standalone ports)On ports NOT in a LAG, no routing makes them act as layer-2 switch ports instead of routed ports. Without this, the port would try to do IP routing.
vlan trunk native 244 (standalone)On standalone trunk ports (not in LAG), sets the native VLAN to 244 — same as the MCLAGs. Ensures consistency regardless of how the downlink is configured.

    active-gateway ip 10.0.44.1

CommandExplanation
interface vlan <n>Creates a Switched Virtual Interface (SVI) — the layer-3 gateway for that VLAN. Devices in the VLAN use this IP as their default gateway. Equivalent to Cisco's interface vlan <n>.
vsx-sync active-gatewaysSynchronizes the active-gateway configuration to the VSX peer. This ensures both switches have the same virtual gateway IP, so failover is seamless.
ip address 10.0.2.42/24The real IP of this SVI on ND4-prim. Used for management, OSPF adjacencies, and as a source IP for traffic originating from this switch. ND4-sec would have 10.0.2.43/24.
active-gateway ip mac 02:02:00:04:41:01Sets the virtual MAC address for the active-gateway. This is a custom MAC (not auto-generated) that both VSX peers share. When either switch responds to ARP for the virtual IP, it uses this MAC. The 02 prefix indicates a locally administered address.

Why custom MAC? Consistent MAC across failover events prevents ARP cache thrashing on endpoints.
active-gateway ip 10.0.2.41The virtual IP address that serves as the default gateway for devices in this VLAN. This is Aruba's equivalent of VRRP/HSRP virtual IP.

• Devices use 10.0.2.41 as their gateway (not .42 or .43)
• ND4-prim (primary) responds to ARP and forwards traffic
• If ND4-prim fails, ND4-sec takes over instantly with the same IP and MAC
• No election, no timers, no failover delay — this is faster than VRRP
ip helper-address 10.0.10.12
(×3 servers)		DHCP relay (IP helper). When a device in VLAN 124 broadcasts a DHCP Discover, the switch forwards it as a unicast to these DHCP servers. Three servers (10.0.10.12, .13, .14) provide redundancy. The switch adds a Relay Agent Information Option (Option 82) with the VLAN and switch info so the DHCP server knows which subnet/pool to assign an IP from.
ip ospf 1 area 0.0.0.0Enables OSPF on this SVI in Area 0 (backbone area). This advertises the VLAN's subnet to other OSPF routers (like the firewall/core). Not all VLANs have OSPF — VLAN 44 (voice) doesn't, keeping it isolated from routing.
💡
Active-Gateway vs VRRP: Aruba's active-gateway is VSX-native and provides sub-second failover because both peers already share the MAC/IP — there's no election process. VRRP has a 3-second default election timer. Active-gateway is only available within a VSX pair, while VRRP works between any vendors.

CommandExplanation
snmp-server community H#@#123Sets the SNMP community string to "H#@#123" (DPA = Damietta Port Authority, ISFP = likely a project code). Better than "public" but should still be SNMPv3 in production.
vsxEnters the VSX configuration context.
system-mac 02:01:00:04:00:04Sets a unique VSX system MAC address. Both VSX peers use this same system-MAC for protocols that need a consistent identifier (like LACP). The 02 prefix = locally administered. This MAC is derived from the chassis and must match on both peers.
inter-switch-link lag 128Tells VSX to use LAG 128 as the ISL. All VSX synchronization data, control plane messages, and cross-peer data traffic flows through this LAG.
role primaryDefines this switch as the VSX primary. The primary handles:
• Active-gateway ARP responses
• STP root bridge role (lower priority)
• Config propagation to secondary

The secondary is in hot standby — it forwards data but doesn't initiate control plane operations until the primary fails.
keepalive peer 10.0.4.42 source 10.0.4.41Configures the keepalive mechanism:
• peer 10.0.4.42 = the secondary switch's keepalive IP
• source 10.0.4.41 = this switch's keepalive IP (on port 1/1/48)

The primary sends periodic keepalive packets (default every 1 second) to the peer. If 3 consecutive keepalives are missed (3 seconds), the peer is declared down and a failover occurs.
vsx-sync vsx-globalSynchronizes the VSX global configuration itself to the peer. This is meta-synchronization — it ensures both switches agree on VSX parameters (role, system-mac, keepalive settings).

CommandExplanation
ip route 0.0.0.0/0 10.0.14.2Default route pointing to the firewall/core router at 10.0.14.2 (VLAN 14). Note the AOS-CX syntax uses /0 CIDR notation (like Cisco XR), not the 0.0.0.0 0.0.0.0 wildcard mask. All internet-bound or external traffic goes here.
router ospf 1Creates OSPF process 1 and enters OSPF configuration mode. Multiple OSPF processes can run on AOS-CX (unlike traditional Cisco IOS).
redistribute connectedInjects all directly connected subnets into OSPF. Any SVI with an IP address (VLAN 2, 14, 124-150, 244) is advertised to OSPF neighbors. This is how the firewall learns about all the VLAN subnets.
redistribute staticInjects static routes (like the default route) into OSPF. This advertises the default route to other OSPF routers, giving them a path to the internet through this switch.
area 0.0.0.0Defines OSPF Area 0 (backbone area). All interfaces with ip ospf 1 area 0.0.0.0 participate in this area. In this single-area design, all OSPF-enabled VLANs are in Area 0 — simple and effective for a campus network.
📌
Routing flow:
1. User in VLAN 124 sends packet to 10.0.124.1 (active-gateway)
2. ND4-prim receives it on SVI vlan 124
3. If destination is local VLAN → switch directly
4. If destination is another VLAN → route via SVI
5. If destination is external → forward to 10.0.14.2 (firewall) via default route
6. OSPF advertises all VLAN subnets to the firewall so it knows how to return traffic

🏗️ Architecture Summary — What We Learned

  • Access Layer (ND2-E204): Simple ArubaOS-Switch. Creates VLANs, assigns access ports, uplinks via LACP trunk. No routing, no HA. Keeps it simple and reliable at the edge.
  • Distribution/Core (ND4-prim): Complex ArubaOS-CX. VSX pair for HA, 47 MCLAGs to access switches, inter-VLAN routing via OSPF, active-gateway for sub-second failover, DHCP relay, sFlow monitoring, centralized logging.
  • VSX provides: Active-active forwarding (not active-standby), MCLAG for multi-chassis link aggregation, active-gateway replacing VRRP with faster failover, ISL for state sync, dedicated keepalive for split-brain prevention.
  • Two different Aruba OSes coexist: ArubaOS-Switch (ProVision) on access switches — simple, mature, CLI风格 like legacy HP. ArubaOS-CX on distribution/core — modern, Linux-based, Cisco-like CLI, REST API, VSX.
  • Native VLAN 244 serves as the management channel between distribution and access. All other VLANs are tagged on MCLAG trunks.
  • OSPF Area 0 with redistribute connected+static — simple single-area design that advertises all VLAN subnets to the firewall.
  • Three DHCP servers (10.0.10.12/13/14) provide redundancy for IP address assignment across all user VLANs.
