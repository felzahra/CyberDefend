Step 1-3

Installation on GNS3

1

Import FortiGate VM Image into GNS3

Add the FortiGate QEMU image to your GNS3 appliance library.

GNS3 → Edit → Preferences → QEMU VMs → New

1. Open GNS3 → Go to Edit → Preferences → QEMU VMs

2. Click New → Select QEMU VM type

3. Name it FortiGate-VM

4. Browse and select the FortiGate-VM64-v7.x.x.qcow2 file

5. Set QEMU binary to qemu-system-x86_64

6. Click Finish

Tip: Make sure the qcow2 file is not compressed (.zip/.gz). Extract it first.
2

Configure VM Resources

Allocate proper RAM and CPU for the FortiGate VM to run smoothly.

FortiGate VM Settings — RAM, CPU, Adapters

GNS3 VM Settings
Configuration 
# In GNS3 → Right-click FortiGate VM → Configure

General:
  Name:          FortiGate-VM
  Category:      Security
  Symbol:        Firewall

System:
  RAM:           2048 MB        # Minimum 1024, recommended 2048+
  CPUs:          2              # Minimum 1, recommended 2
  Console type:  telnet

Network:
  Adapters:      4              # port1(LAN), port2(DMZ), port3(WAN), port4(mgmt)
  Type:          e1000

  QEMU options:  -smp 2 -m 2048
  Priority:      Normal
Warning: Do NOT set RAM below 1024MB. FortiGate VM will crash or fail to boot. 2048MB is the safe minimum for lab use.

Step 6

Interface Configuration

Configure IP addresses on each physical port and assign them to security zones.

6

Configure port1 (LAN), port2 (DMZ), port3 (WAN)

Assign IP addresses and bring interfaces up.

FortiGate GUI → Network → Interfaces (same can be done via CLI below)

Interface IP Configuration 
###### ============================================ ######
######  PORT 1 — LAN INTERFACE (192.168.1.1/24)  ######
###### ============================================ ######

config system interface
    edit "port1"
        set alias "LAN"
        set ip 192.168.1.1 255.255.255.0
        # Assign to LAN zone
        set zone "lan"
        # Enable the interface
        set status up
        # Allow management access (for lab purposes)
        set allowaccess ping https ssh http
    next

###### ============================================= ######
######  PORT 2 — DMZ INTERFACE (172.16.1.1/24)   ######
###### ============================================= ######

    edit "port2"
        set alias "DMZ"
        set ip 172.16.1.1 255.255.255.0
        # Assign to DMZ zone
        set zone "dmz"
        set status up
        set allowaccess ping https ssh
    next

###### ============================================= ######
######  PORT 3 — WAN INTERFACE (10.0.0.2/30)     ######
###### ============================================= ######

    edit "port3"
        set alias "WAN"
        set ip 10.0.0.2 255.255.255.252
        # Assign to WAN zone
        set zone "wan"
        set status up
        set allowaccess ping
    next
end

# Verify all interfaces
get system interface physical
# == [ port1 ]
#    alias: LAN   ip: 192.168.1.1 255.255.255.0
#    status: up   zone: lan   speed: 1000Mbps
# == [ port2 ]
#    alias: DMZ   ip: 172.16.1.1 255.255.255.0
#    status: up   zone: dmz   speed: 1000Mbps
# == [ port3 ]
#    alias: WAN   ip: 10.0.0.2 255.255.255.252
#    status: up   zone: wan   speed: 1000Mbps
Zone Assignment: FortiGate automatically creates default zones (lan, wan, dmz). When you use set zone "lan", it assigns the interface to the built-in LAN zone. You can verify zones with show system zone.
Step 7

DHCP Server Configuration

Set up DHCP servers on LAN and DMZ to automatically assign IP addresses to all PCs.

7

Create DHCP Servers for LAN & DMZ

VPCS nodes will receive IPs automatically via DHCP.

DHCP Server Setup 
###### ============================== ######
######  DHCP SERVER ON LAN (port1)   ######
###### ============================== ######

config system dhcp server
    edit 1
        # Bind to LAN interface
        set interface "port1"
        # Enable the server
        set status enable
        # DHCP range for LAN PCs
        set lease-time 86400
        config ip-range
            edit 1
                set start-ip 192.168.1.10
                set end-ip 192.168.1.100
            next
        end
        # Default gateway and DNS
        set default-gateway 192.168.1.1
        set dns-server1 8.8.8.8
        set dns-server2 8.8.4.4
    next

###### =============================== ######
######  DHCP SERVER ON DMZ (port2)    ######
###### =============================== ######

    edit 2
        # Bind to DMZ interface
        set interface "port2"
        set status enable
        set lease-time 86400
        config ip-range
            edit 1
                # Range for DMZ PCs (PC-DMZ1 and PC-DMZ2)
                set start-ip 172.16.1.10
                set end-ip 172.16.1.20
            next
        end
        # DMZ default gateway
        set default-gateway 172.16.1.1
        set dns-server1 8.8.8.8
    next
end

# Verify DHCP servers
show system dhcp server
# Server 1: port1  status=enable  range=192.168.1.10-100
# Server 2: port2  status=enable  range=172.16.1.10-20

Routing & NAT Configuration

Set up the default route pointing to the WAN and configure outbound NAT for internet access.

8

Default Route & Outbound NAT

Configure routing so internal hosts can reach external networks.

FortiGate → Router → Static Routes

Routing & NAT 
###### ============================== ######
######    DEFAULT ROUTE (WAN)        ######
###### ============================== ######

config router static
    edit 0
        # Route all traffic (0.0.0.0/0) to WAN gateway
        set dst 0.0.0.0 0.0.0.0
        set gateway 10.0.0.1
        # Exit via port3 (WAN interface)
        set device "port3"
        # Set distance (administrative distance)
        set distance 10
    next
end

# Verify routing table
get router info routing-table all
# Routing table for VRF=0
# S*      0.0.0.0/0 [10/0] via 10.0.0.1, port3
# C       192.168.1.0/24 is directly connected, port1
# C       172.16.1.0/24 is directly connected, port2
# C       10.0.0.0/30 is directly connected, port3


###### ======================================= ######
######  OUTBOUND NAT (IP Masquerade / Overload) ######
###### ======================================= ######

config firewall policy
    # First, check if NAT is enabled by default on policies
    # (In FortiOS, each policy has its own NAT setting)
end

# FortiOS uses "NAT" flag per-policy, not a separate NAT table.
# When creating firewall policies in the next section,
# we will set "set nat enable" on outbound policies.
# This performs IP masquerade (source NAT / overload).

# Verify current NAT settings
show system settings
# Check: opmode is "nat" (should be default)

# If operation mode is NOT nat, change it:
config system settings
    set opmode nat
end
FortiOS NAT Model: Unlike Cisco ASA or iptables, FortiGate doesn't use a separate NAT configuration. NAT is a per-policy setting. Each firewall policy can have set nat enable which translates the source IP to the outgoing interface IP.
Step 9

Firewall Policies — Permit & Deny

This is the core of the lab. We create 5 policies that control traffic between LAN, DMZ, and WAN zones — some permitting traffic, some explicitly denying it.

FortiGate GUI → Policy & Objects → IPv4 Policy — Final result

Policy 1 PERMIT

LAN → WAN

Outbound internet with NAT

Policy 2 PERMIT

LAN → DMZ

Access DMZ servers from LAN

Policy 3 PERMIT

DMZ → WAN

DMZ servers update via internet

Policy 4 DENY

DMZ → LAN

Block DMZ from accessing LAN

Policy 5 DENY

WAN → LAN

Block all inbound from internet

Implicit DENY

All Other

Default deny-all at bottom

9

All 5 Firewall Policies — Full CLI

Create all policies in order. FortiGate processes policies top-to-bottom.

Complete Firewall Policy Configuration 
config firewall policy

############################################################
#  POLICY 1: LAN → WAN (PERMIT + NAT)                      #
#  Purpose: Allow LAN users to access the internet          #
#  Action: PERMIT with source NAT (masquerade)              #
############################################################
    edit 1
        set name "LAN-to-WAN-Permit"
        set srcintf "port1"              # Source: LAN interface
        set dstintf "port3"              # Destination: WAN interface
        set srcaddr "all"                # Any source IP (192.168.1.0/24)
        set dstaddr "all"                # Any destination IP
        set action accept                # ★ PERMIT traffic
        set schedule "always"            # Active all the time
        set service "ALL"                # All protocols (TCP/UDP/ICMP)
        set nat enable                   # ★ Enable source NAT
        set logtraffic all               # Log all sessions
        set comments "Allow LAN internet access with NAT"
    next

############################################################
#  POLICY 2: LAN → DMZ (PERMIT)                            #
#  Purpose: Allow LAN users to access DMZ servers           #
#  Action: PERMIT, no NAT (same internal network context)   #
############################################################
    edit 2
        set name "LAN-to-DMZ-Permit"
        set srcintf "port1"              # Source: LAN
        set dstintf "port2"              # Destination: DMZ
        set srcaddr "all"
        set dstaddr "all"
        set action accept                # ★ PERMIT traffic
        set schedule "always"
        set service "ALL"
        set nat disable                  # No NAT for internal-to-internal
        set logtraffic all
        set comments "Allow LAN to reach DMZ servers"
    next

############################################################
#  POLICY 3: DMZ → WAN (PERMIT + NAT)                      #
#  Purpose: Allow DMZ servers to reach internet             #
#  (e.g., for updates, API calls, etc.)                     #
############################################################
    edit 3
        set name "DMZ-to-WAN-Permit"
        set srcintf "port2"              # Source: DMZ
        set dstintf "port3"              # Destination: WAN
        set srcaddr "all"
        set dstaddr "all"
        set action accept                # ★ PERMIT traffic
        set schedule "always"
        set service "ALL"
        set nat enable                   # ★ Enable source NAT
        set logtraffic all
        set comments "Allow DMZ servers outbound internet"
    next

############################################################
#  POLICY 4: DMZ → LAN (DENY) ★ EXPLICIT DENY ★           #
#  Purpose: Block DMZ from initiating connections to LAN    #
#  Why: If a DMZ server is compromised, attacker           #
#  cannot pivot into the LAN network                        #
############################################################
    edit 4
        set name "DMZ-to-LAN-DENY"
        set srcintf "port2"              # Source: DMZ
        set dstintf "port1"              # Destination: LAN
        set srcaddr "all"
        set dstaddr "all"
        set action deny                  # ★★★ DENY traffic ★★★
        set schedule "always"
        set service "ALL"
        set logtraffic all               # Log denied attempts!
        set comments "BLOCK DMZ from accessing LAN (security)"
    next

############################################################
#  POLICY 5: WAN → LAN (DENY) ★ EXPLICIT DENY ★           #
#  Purpose: Block all unsolicited inbound traffic          #
#  Why: No external host can reach internal LAN directly   #
############################################################
    edit 5
        set name "WAN-to-LAN-DENY"
        set srcintf "port3"              # Source: WAN (internet)
        set dstintf "port1"              # Destination: LAN
        set srcaddr "all"
        set dstaddr "all"
        set action deny                  # ★★★ DENY traffic ★★★
        set schedule "always"
        set service "ALL"
        set logtraffic all               # Log for security monitoring
        set comments "BLOCK all inbound internet to LAN"
    next

end

# ============================================================
# NOTE: FortiGate has an IMPLICIT DENY at the bottom of the   
# policy list. Any traffic not matching policies 1-5 will be  
# automatically dropped. For example:                          
#   - WAN → DMZ: DENIED (implicit)                            
#   - DMZ → DMZ (same interface): handled by local-in policy  
# ============================================================
Policy 1 — LAN → WAN
Source: port1 (LAN)
Dest: port3 (WAN)
Action: ACCEPT
NAT: ENABLE

LAN users can browse the internet. Source IP is NATed to 10.0.0.2.

Policy 2 — LAN → DMZ
Source: port1 (LAN)
Dest: port2 (DMZ)
Action: ACCEPT
NAT: DISABLE

LAN PCs can reach DMZ servers (PC-DMZ1, PC-DMZ2) at 172.16.1.x. No NAT needed internally.

Policy 3 — DMZ → WAN
Source: port2 (DMZ)
Dest: port3 (WAN)
Action: ACCEPT
NAT: ENABLE

DMZ servers can reach the internet (e.g., for OS updates, API calls). NATed to 10.0.0.2.

Policy 4 — DMZ → LAN (DENY)
Source: port2 (DMZ)
Dest: port1 (LAN)
Action: DENY
Log: ALL
Why explicit deny? Even though the implicit deny would catch this, we create an explicit deny policy with logging so we can detect if a compromised DMZ server is attempting to scan or access the LAN. This is a security best practice.
Policy 5 — WAN → LAN (DENY)
Source: port3 (WAN)
Dest: port1 (LAN)
Action: DENY
Log: ALL
Why explicit deny? Blocks ALL unsolicited inbound traffic from the internet to the LAN. Logged attempts help identify port scanning or attack attempts from outside.
Implicit Deny — All Other Traffic

Any traffic not matching policies 1-5 is automatically dropped by FortiGate's implicit deny. For example, WAN → DMZ traffic is denied because no policy permits it.

Policy Decision Flow

Incoming Packet
Match Policy 1-3? → ACCEPT (with/without NAT)
Match Policy 4-5? → DENY + LOG
No match? → IMPLICIT DENY (dropped silently)

Common Issues

FortiGate won't boot

Increase RAM to 2048MB+. Make sure QEMU binary is correct. Check GNS3 server has enough resources.

Can't login after boot

Wait 3-5 minutes after boot. Try both admin/(blank) and maintainer/password.

VPCS can't get DHCP

Verify interface is UP. Check DHCP server is bound to correct interface. Ensure no typos in IP range. Try dhcp -r to release/renew.

Ping works but should be denied

Check policy order! FortiGate matches top-to-bottom. Use get firewall policy stat to see which policy is matching.

DMZ PCs can't reach each other

Same-zone traffic (port2→port2) is handled by intra-zone policy. Check set intrazone allow in firewall settings if needed.

Save your config! After everything works, save the configuration: execute save. Also save GNS3 project to preserve the topology.

# ==========================================
# FortiGate GNS3 Lab - Complete Config
# 3 Zones: LAN, DMZ, WAN with 2 DMZ PCs
# ==========================================

# --- System Settings ---
config system global
    set hostname FG-LAB
    set admin-password "Admin@123#"
    set timezone 05
end

# --- Interfaces ---
config system interface
    edit "port1"
        set alias "LAN" set ip 192.168.1.1 255.255.255.0
        set zone "lan" set status up
        set allowaccess ping https ssh http
    next
    edit "port2"
        set alias "DMZ" set ip 172.16.1.1 255.255.255.0
        set zone "dmz" set status up
        set allowaccess ping https ssh
    next
    edit "port3"
        set alias "WAN" set ip 10.0.0.2 255.255.255.252
        set zone "wan" set status up
        set allowaccess ping
    next
end

# --- DHCP Servers ---
config system dhcp server
    edit 1
        set interface "port1" set status enable
        set lease-time 86400
        set default-gateway 192.168.1.1
        set dns-server1 8.8.8.8
        config ip-range
            edit 1
                set start-ip 192.168.1.10
                set end-ip 192.168.1.100
            next
        end
    next
    edit 2
        set interface "port2" set status enable
        set lease-time 86400
        set default-gateway 172.16.1.1
        set dns-server1 8.8.8.8
        config ip-range
            edit 1
                set start-ip 172.16.1.10
                set end-ip 172.16.1.20
            next
        end
    next
end

# --- Routing ---
config router static
    edit 0
        set dst 0.0.0.0 0.0.0.0
        set gateway 10.0.0.1
        set device "port3"
    next
end

# --- Firewall Policies ---
config firewall policy
    edit 1
        set name "LAN-to-WAN-Permit"
        set srcintf "port1" set dstintf "port3"
        set srcaddr "all" set dstaddr "all"
        set action accept set schedule "always"
        set service "ALL" set nat enable
        set logtraffic all
    next
    edit 2
        set name "LAN-to-DMZ-Permit"
        set srcintf "port1" set dstintf "port2"
        set srcaddr "all" set dstaddr "all"
        set action accept set schedule "always"
        set service "ALL" set nat disable
        set logtraffic all
    next
    edit 3
        set name "DMZ-to-WAN-Permit"
        set srcintf "port2" set dstintf "port3"
        set srcaddr "all" set dstaddr "all"
        set action accept set schedule "always"
        set service "ALL" set nat enable
        set logtraffic all
    next
    edit 4
        set name "DMZ-to-LAN-DENY"
        set srcintf "port2" set dstintf "port1"
        set srcaddr "all" set dstaddr "all"
        set action deny set schedule "always"
        set service "ALL" set logtraffic all
    next
    edit 5
        set name "WAN-to-LAN-DENY"
        set srcintf "port3" set dstintf "port1"
        set srcaddr "all" set dstaddr "all"
        set action deny set schedule "always"
        set service "ALL" set logtraffic all
    next
end

# --- Save ---
execute save
# Configuration saved to file
