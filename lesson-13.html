Section 01

What is Cloud Computing?

On-demand delivery of computing resources over the internet with pay-as-you-go pricing.

Cloud Computing Overview

On-Demand Self-Service

Provision resources automatically without human interaction.

Broad Network Access

Access via standard mechanisms from any device.

Resource Pooling

Multi-tenant model with dynamic assignment.

Rapid Elasticity

Scale out/in quickly to match demand.

Measured Service

Pay only for what you use — metered billing.

Section 02

Cloud Service Models

Three core service models with different levels of managed responsibility.

IaaS / PaaS / SaaS Stack

IaaS — Infrastructure as a Service

You manage: OS, Runtime, Data, Apps

Virtual machines, storage, networking. Provider manages physical hardware.

AWS EC2 Azure VMs GCP Compute Engine DigitalOcean Droplets

PaaS — Platform as a Service

You manage: Data, Apps only

Runtime, OS, middleware managed by provider. Focus on code.

AWS Elastic Beanstalk Azure App Service GCP App Engine Heroku

SaaS — Software as a Service

You manage: Nothing — fully managed

Complete application delivered over the browser. Provider manages everything.

Office 365 Gmail / Workspace Salesforce Slack
Section 03

Deployment Models

How cloud infrastructure is hosted and who has access to it.

Cloud Deployment Models

Public Cloud

Shared infrastructure, open to the public. Pay-per-use. Highest scalability.

✓ No upfront cost

✓ Infinite scalability

✗ Less control over infrastructure

✗ Compliance concerns

Private Cloud

Dedicated to one organization. On-premises or hosted. Full control.

✓ Full control & customization

✓ Compliance & security

✗ High upfront cost

✗ Limited scalability

Hybrid Cloud

Mix of public + private. Workloads move between them. Best of both.

✓ Flexibility & cost balance

✓ Burst to public on demand

✗ Complex networking

✗ Requires integration skills

Section 06

Security & IAM

IAM Policy Example

iam-policy.json
{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": [ "ec2:DescribeInstances", "ec2:StartInstances", "ec2:StopInstances", "ec2:RebootInstances" ], "Resource": "arn:aws:ec2:us-east-1:123456789012:instance/*", "Condition": { "IpAddress": { "aws:SourceIp": ["203.0.113.0/24"] } } }, { "Effect": "Deny", "Action": "ec2:TerminateInstances", "Resource": "*" } ] }

Do

  • ✓ Use MFA for all users
  • ✓ Apply least-privilege IAM
  • ✓ Enable CloudTrail logging
  • ✓ Encrypt data at rest & in transit
  • ✓ Use security groups not NACLs for app control
  • ✓ Rotate access keys every 90 days

Don't

  • ✗ Never use root account for daily tasks
  • ✗ Never embed credentials in code
  • ✗ Never open 0.0.0.0/0 to SSH/RDP
  • ✗ Never store sensitive data in S3 without encryption
  • ✗ Never skip security group review
  • ✗ Never ignore IAM Access Analyzer findings

Hands-On Labs

Lab 1 Launch a Web Server on EC2

lab-ec2-webserver.sh
#!/bin/bash # Step 1: Create key pair $ aws ec2 create-key-pair \ --key-name lab-key \ --query 'KeyMaterial' \ --output text > lab-key.pem $ chmod 400 lab-key.pem # Step 2: Create security group $ aws ec2 create-security-group \ --group-name web-sg \ --description "Web Server SG" $ aws ec2 authorize-security-group-ingress \ --group-name web-sg \ --protocol tcp --port 22 --cidr 0.0.0.0/0 $ aws ec2 authorize-security-group-ingress \ --group-name web-sg \ --protocol tcp --port 80 --cidr 0.0.0.0/0 # Step 3: Launch instance with user data $ aws ec2 run-instances \ --image-id ami-0c02fb55956c7d316 \ --instance-type t3.micro \ --key-name lab-key \ --security-groups web-sg \ --user-data file://install-web.sh # install-web.sh content: #!/bin/bash yum update -y yum install -y httpd systemctl start httpd systemctl enable httpd echo "<h1>Hello from EC2!</h1>" > /var/www/html/index.html

Lab 2 Static Website on S3

lab-s3-website.sh
# Create bucket (must be globally unique name) $ aws s3 mb s3://my-static-site-2024-abc \ --region us-east-1 # Upload website files $ aws s3 sync ./website/ s3://my-static-site-2024-abc/ # Enable static website hosting $ aws s3 website s3://my-static-site-2024-abc/ \ --index-document index.html \ --error-document error.html # Set public read policy $ aws s3api put-bucket-policy \ --bucket my-static-site-2024-abc \ --policy '{"Statement":[{"Effect":"Allow","Principal":"*","Action":"s3:GetObject","Resource":"arn:aws:s3:::my-static-site-2024-abc/*"}]}' # Open website $ echo "Site URL: http://my-static-site-2024-abc.s3-website-us-east-1.amazonaws.com"

Lab 3 Build a Custom VPC

lab-vpc-custom.sh
#!/bin/bash VPC_CIDR="10.1.0.0/16" REGION="us-east-1" # Create VPC VPC_ID=$(aws ec2 create-vpc \ --cidr-block $VPC_CIDR \ --query 'Vpc.VpcId' --output text) echo "Created VPC: $VPC_ID" # Create public & private subnets PUB_SUB=$(aws ec2 create-subnet \ --vpc-id $VPC_ID --cidr-block "10.1.1.0/24" \ --availability-zone "${REGION}a" \ --query 'Subnet.SubnetId' --output text) PRI_SUB=$(aws ec2 create-subnet \ --vpc-id $VPC_ID --cidr-block "10.1.10.0/24" \ --availability-zone "${REGION}a" \ --query 'Subnet.SubnetId' --output text) # Enable auto-assign public IP on public subnet $ aws ec2 modify-subnet-attribute \ --subnet-id $PUB_SUB \ --map-public-ip-on-launch # Create IGW, attach, add route IGW_ID=$(aws ec2 create-internet-gateway \ --query 'InternetGateway.InternetGatewayId' --output text) $ aws ec2 attach-internet-gateway \ --internet-gateway-id $IGW_ID --vpc-id $VPC_ID RT_ID=$(aws ec2 describe-route-tables \ --filters "Name=vpc-id,Values=${VPC_ID}" \ --query 'RouteTables[0].RouteTableId' --output text) $ aws ec2 create-route \ --route-table-id $RT_ID \ --destination-cidr-block "0.0.0.0/0" \ --gateway-id $IGW_ID echo "Public Subnet: $PUB_SUB" echo "Private Subnet: $PRI_SUB" echo "Internet GW: $IGW_ID" echo "VPC complete!"
