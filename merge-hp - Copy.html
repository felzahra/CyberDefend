• Cisco and Aruba are similar (both derived from classic CLI)

Part 1 — ND1-E101 (Access Switch) 24 Ethernet ports + 2 Gigabit uplinks · Comware v5.20

1
Set Hostname & Super Password
Name the switch for identification and set a privileged (Level 3) password to protect admin access.
ND1-E101 — ACCESS SWITCH
<ND1-E101> system-view
! Enter system view (global config mode)

[ND1-E101] sysname ND1-E101
! Set the switch hostname to ND1-E101
! This name appears in CLI prompts and logs

[ND1-E101] super password level 3 cipher YourStrongPass123
! Set Level 3 (management) super password
! 'cipher' stores it encrypted in running-config
! Used when elevating from lower privilege levels
ℹ️
Comware Privilege Levels: Level 0 = Visit, Level 1 = Monitor, Level 2 = Configuration, Level 3 = Management (full admin). Always set a super password for Level 3.

Enable Telnet & SSH Server
Activate remote management protocols so administrators can access the switch without a console cable.
ND1-E101 — ACCESS SWITCH
[ND1-E101] telnet server enable
! Enable the Telnet server for remote CLI access
! Telnet is unencrypted — use SSH in production

[ND1-E101] ssh server enable
! Enable the SSH server for secure remote access
! Requires RSA/DSA key pair to be generated first

[ND1-E101] ip https enable
! Enable the web-based management interface (HTTPS)
⚠️
Security Note: In a production environment, disable Telnet and use only SSH. Telnet transmits credentials in plain text. Keep it enabled in the lab for learning purposes only.

Configure Access Ports — VLAN 50 with PoE & Edge STP
Configure Ethernet 1/0/1 through 1/0/22 as hybrid access ports for VLAN 50 (bahrya). Enable PoE for APs and STP edge port for fast convergence.
⚡ Applied to ports: Ethernet1/0/1, Ethernet1/0/2, Ethernet1/0/3, Ethernet1/0/4, Ethernet1/0/5, Ethernet1/0/6, Ethernet1/0/7, Ethernet1/0/8, Ethernet1/0/9, Ethernet1/0/10, Ethernet1/0/11, Ethernet1/0/12, Ethernet1/0/13, Ethernet1/0/14, Ethernet1/0/15, Ethernet1/0/16, Ethernet1/0/17, Ethernet1/0/18, Ethernet1/0/19, Ethernet1/0/20, Ethernet1/0/21, Ethernet1/0/22
ND1-E101 — ACCESS SWITCH (Example for E1/0/1)
[ND1-E101] interface Ethernet1/0/1
[ND1-E101-Ethernet1/0/1] port link-type hybrid
! Set port to hybrid mode (Comware's flexible port type)
! Hybrid can tag some VLANs and untag others

[ND1-E101-Ethernet1/0/1] undo port hybrid vlan 1
! Remove VLAN 1 from the hybrid allowed list
! Security best practice — don't leak traffic to default VLAN

[ND1-E101-Ethernet1/0/1] port hybrid vlan 50 untagged
! Add VLAN 50 as untagged — connected device sees no VLAN tag
! This makes it behave like an access port for VLAN 50

[ND1-E101-Ethernet1/0/1] port hybrid pvid vlan 50
! Set the Port VLAN ID (PVID) to 50
! Untagged incoming frames are assigned to VLAN 50

[ND1-E101-Ethernet1/0/1] poe enable
! Enable Power over Ethernet on this port
! Powers connected wireless access points (802.3af/at)

[ND1-E101-Ethernet1/0/1] stp edged-port enable
! Set as STP edge port (same as Cisco PortFast)
! Skips STP listening/learning — goes directly to forwarding
! Prevents 30-50 second delay when device connects

[ND1-E101-Ethernet1/0/1] quit
💡
Repeat for E1/0/2 through E1/0/22: Every access port has the exact same configuration. In production, use port-group or a script to apply to all ports at once. In the simulator, configure each port individually for learning.
ND1-E101 — BULK CONFIG (All 22 ports)
! Repeat this block for ports 2 through 22:
interface Ethernet1/0/2
 port link-type hybrid
 undo port hybrid vlan 1
 port hybrid vlan 50 untagged
 port hybrid pvid vlan 50
 poe enable
 stp edged-port enable
quit

! ... repeat for Ethernet1/0/3 through Ethernet1/0/22
! (Same 6 commands per port)
ℹ️
Why Hybrid not Access? Comware's "hybrid" mode is more flexible than "access". An access port can only belong to one VLAN. A hybrid port can carry multiple VLANs — some tagged, some untagged. Using hybrid with a single untagged VLAN achieves the same result as access mode but gives you room to add a voice VLAN later.

9
Configure Link Aggregation Uplink — GE1/0/25 & GE1/0/26
Create a dynamic LAG (Link Aggregation Group 1) using both Gigabit ports for high-bandwidth, redundant uplink to ND6. Enable fiber combo mode.
ND1-E101 — ACCESS SWITCH
! --- Step A: Create the Link Aggregation Group ---
[ND1-E101] interface Bridge-Aggregation1
[ND1-E101-Bridge-Aggregation1] description Connection-to-ND6
[ND1-E101-Bridge-Aggregation1] port link-type trunk
[ND1-E101-Bridge-Aggregation1] port trunk permit vlan all
[ND1-E101-Bridge-Aggregation1] port trunk pvid vlan 241
[ND1-E101-Bridge-Aggregation1] link-aggregation mode dynamic
! Use LACP (dynamic) instead of static mode
! LACP detects misconfigurations and prevents loops
[ND1-E101-Bridge-Aggregation1] quit

! --- Step B: Assign physical ports to the group ---
[ND1-E101] interface GigabitEthernet1/0/25
[ND1-E101-GigabitEthernet1/0/25] port link-type trunk
[ND1-E101-GigabitEthernet1/0/25] port trunk permit vlan all
[ND1-E101-GigabitEthernet1/0/25] port trunk pvid vlan 241
[ND1-E101-GigabitEthernet1/0/25] combo enable fiber
! Switch the combo port to use the SFP fiber interface
! (instead of the copper RJ45)
[ND1-E101-GigabitEthernet1/0/25] port link-aggregation group 1
! Bind this physical port to LAG group 1
[ND1-E101-GigabitEthernet1/0/25] quit

! Repeat for the second member port:
[ND1-E101] interface GigabitEthernet1/0/26
[ND1-E101-GigabitEthernet1/0/26] port link-type trunk
[ND1-E101-GigabitEthernet1/0/26] port trunk permit vlan all
[ND1-E101-GigabitEthernet1/0/26] port trunk pvid vlan 241
[ND1-E101-GigabitEthernet1/0/26] combo enable fiber
[ND1-E101-GigabitEthernet1/0/26] port link-aggregation group 1
[ND1-E101-GigabitEthernet1/0/26] quit
ℹ️
Dynamic vs Static LAG: Dynamic mode uses LACP (IEEE 802.3ad) to negotiate the aggregation. Static mode just bundles ports without negotiation. Always prefer dynamic — if one side is misconfigured, LACP won't form the aggregation, preventing broadcast storms.

Configure SNMP
Enable SNMP v2c with read-only community "H#@#123" and configure trap destination to the NMS server at 10.0.10.162.
ND1-E101 — ACCESS SWITCH
[ND1-E101] snmp-agent
! Enable the SNMP agent process

[ND1-E101] snmp-agent sys-info version all
! Enable all SNMP versions (v1, v2c, v3)

[ND1-E101] snmp-agent community read H#@#123
! Set read-only community string for SNMP v2c
! NMS can poll switch status but cannot modify config

[ND1-E101] snmp-agent log all
! Enable SNMP logging for all operations

[ND1-E101] snmp-agent target-host trap address udp-domain 10.0.10.162 params securityname H#@#123 v2c
! Configure SNMP trap destination (NMS server)
! Traps are unsolicited notifications (alerts, errors)
! Sent via UDP to 10.0.10.162 using v2c with community "H#@#123"

[ND1-E101] snmp-agent trap enable default-route
! Enable default-route change traps

[ND1-E101] snmp-agent trap queue-size 500
! Set trap queue size to 500 messages

[ND1-E101] snmp-agent trap life 600
! Set trap message lifetime to 600 seconds
! If trap can't be sent within 600s, it's discarded
⚠️
Security Note: SNMP v2c uses plain-text community strings — anyone who knows "H#@#123" can read your switch data. In production, use SNMP v3 with authentication and encryption. The distribution switch (ND1) shows v3 configuration in Part 2.

Configure VTY Lines & Password Recovery
Set all 16 VTY lines (0-15) to use scheme authentication (username/password login) and enable password recovery as a safety net.
ND1-E101 — ACCESS SWITCH
[ND1-E101] password-recovery enable
! Allow password recovery via boot menu
! If you lose the password, you can boot and reset it
! Disable in high-security environments

[ND1-E101] user-interface vty 0 15
[ND1-E101-ui-vty0-15] authentication-mode scheme
! Use "scheme" = username + password authentication
! This uses the local-user accounts (manager / monitor)
! Alternative: "password" = simple password only (less secure)

[ND1-E101-ui-vty0-15] protocol inbound telnet
! Allow only Telnet inbound on VTY lines
! Use "protocol inbound ssh" for SSH-only access
! Use "protocol inbound all" for both

[ND1-E101-ui-vty0-15] quit

! --- SAVE CONFIGURATION ---
[ND1-E101] return
<ND1-E101> save
! Save running-config to startup-config
! Without this, all changes are lost on reboot!
💡
Always save! HP Comware does NOT auto-save. Run save after every configuration session. Verify with display current-configuration.

Configure Trunk Ports with sFlow Monitoring — Module 2
Module 2 ports carry trunk traffic AND have sFlow sampling enabled for network traffic analysis. Some ports have flow sampling, others only counter sampling.
ND1 — DISTRIBUTION (GE2/0/1 with sFlow — LAG 1)
[ND1] interface GigabitEthernet2/0/1
[ND1-GigabitEthernet2/0/1] port link-mode bridge
[ND1-GigabitEthernet2/0/1] port link-type trunk
[ND1-GigabitEthernet2/0/1] port trunk permit vlan all
[ND1-GigabitEthernet2/0/1] port trunk pvid vlan 241

! --- sFlow Configuration on this port ---
[ND1-GigabitEthernet2/0/1] sflow flow collector 1
! Send flow samples to collector 1 (defined globally)
[ND1-GigabitEthernet2/0/1] sflow counter interval 30
! Send interface counter data every 30 seconds
[ND1-GigabitEthernet2/0/1] sflow counter collector 1
! Send counter samples to collector 1

[ND1-GigabitEthernet2/0/1] port link-aggregation group 1
[ND1-GigabitEthernet2/0/1] quit
ND1 — WITH FLOW SAMPLING (GE2/0/2 — LAG 2)
[ND1] interface GigabitEthernet2/0/2
[ND1-GigabitEthernet2/0/2] port link-mode bridge
[ND1-GigabitEthernet2/0/2] port link-type trunk
[ND1-GigabitEthernet2/0/2] port trunk permit vlan all
[ND1-GigabitEthernet2/0/2] port trunk pvid vlan 241

! --- sFlow with BOTH flow and counter sampling ---
[ND1-GigabitEthernet2/0/2] sflow sampling-rate 1000
! Sample 1 out of every 1000 packets for flow analysis
! Lower rate = more accurate but more CPU/load
[ND1-GigabitEthernet2/0/2] sflow flow collector 1
[ND1-GigabitEthernet2/0/2] sflow counter interval 30
[ND1-GigabitEthernet2/0/2] sflow counter collector 1

[ND1-GigabitEthernet2/0/2] port link-aggregation group 2
[ND1-GigabitEthernet2/0/2] quit
ℹ️
sFlow vs NetFlow: sFlow (sampled flow) sends statistical samples — lightweight and scalable. NetFlow/IPFIX sends records for every flow — more accurate but heavier. sFlow is preferred on high-throughput distribution switches. The collector at 10.0.10.76 receives all sFlow data (defined globally in Step 2.8).

Configure OSPF Routing
Enable OSPF process 1 in Area 0. Advertise the uplink subnet (10.0.11.0/24) and import direct routes and static routes into OSPF.
ND1 — DISTRIBUTION — OSPF
[ND1] ospf 1
! Create OSPF process 1

[ND1-ospf-1] import-route direct
! Redistribute directly connected subnets into OSPF
! This advertises all local VLAN interfaces

VLAN 1 — Default VLAN

CommandExplanation
name "DEFAULT_VLAN"Assigns a human-readable name. VLAN 1 exists by default on all ArubaOS-Switch ports.

ipv6 enableEnables IPv6 processing on this VLAN interface.

VLAN 98 — Data VLAN (User Ports)

CommandExplanation
untagged 1-8Assigns ports 1 through 8 as untagged (access) members of VLAN 98. Devices plugged into these ports send/receive untagged Ethernet frames — the switch automatically adds/removes the VLAN 98 tag internally. This is equivalent to Cisco's switchport access vlan 98.
tagged Trk1Makes Trk1 a tagged member of VLAN 98. Frames going out Trk1 toward the distribution switch carry an 802.1Q tag with VLAN ID 98. This is how the distribution switch knows which VLAN the traffic belongs to. Equivalent to Cisco's switchport trunk allowed vlan add 98.
no ip addressExplicitly removes any IP address from the VLAN 98 SVI. This switch doesn't need to route for VLAN 98 — the distribution core handles inter-VLAN routing.

CommandExplanation
untagged Trk1Trk1 is an untagged member of VLAN 242. This means management traffic between this switch and the distribution core on VLAN 242 flows without 802.1Q tags on this trunk.

⚠ Important: In ArubaOS-Switch, a port can only be untagged in ONE VLAN. Since Trk1 is untagged in VLAN 242, all other VLANs (like 98) must be tagged on Trk1. VLAN 242 acts as the "native VLAN" for this trunk.

spanning-tree mode rpvstSets the spanning tree mode to RPVST (Rapid Per-VLAN Spanning Tree). This is the ArubaOS-CX equivalent of Cisco's spanning-tree mode rapid-pvst.

• Rapid = uses RSTP (802.1w) for fast convergence (sub-second instead of 50 seconds)

CommandExplanation
interface lag <n> multi-chassisCreates a Multi-Chassis LAG (MCLAG). Unlike a regular LAG that bundles ports on a single switch, an MCLAG spans two physical switches (ND4-prim + ND4-sec). The access switch sees both distribution switches as a single logical device. If one distribution switch fails, the access switch's LACP detects the failure and reroutes through the surviving switch — no STP reconvergence needed.
vsx-sync vlansSynchronizes this LAG's VLAN configuration to the VSX peer. Ensures both sides of the MCLAG have identical VLAN allowlists.
no shutdownAdministratively enables the LAG interface.
no routingDisables IP routing on this LAG — it's a pure layer-2 trunk. No IP packets are processed directly on this interface; routing happens on the SVIs.
vlan trunk native 244Sets VLAN 244 as the native (untagged) VLAN on this trunk. Frames on VLAN 244 are sent without 802.1Q tags. This is the management channel to access switches — matching the access switch config where VLAN 242/244 is untagged on the uplink.

⚠ Note: The native VLAN must match on BOTH ends. Mismatched native VLANs cause silent connectivity issues.
vlan trunk allowed allAllows all VLANs on this trunk. Every VLAN created on the switch (1, 2, 4, 14, 34, 44, 124-150, 200, 244, 999) can pass through this MCLAG. This simplifies config since all access switches potentially need all VLANs.
lacp mode activeEnables LACP in active mode. The switch actively sends LACPDU frames to negotiate the link aggregation. The access switch (ArubaOS-Switch) also uses LACP, so both sides actively negotiate. Active-active is the standard for Aruba MCLAGs.
🏗️
Why 47 MCLAGs? Each MCLAG connects to a different access switch. With 47 access switches in the building, each gets its own MCLAG for isolation and independent failover. One MCLAG failure doesn't affect others.
⚠️
Not all MCLAGs have physical ports assigned on this switch. Some MCLAGs (e.g., lag 2, 5, 22) have no lag <n> assignment under any physical interface on ND4-prim — those ports are on ND4-sec. The MCLAG config exists on both switches for VSX sync consistency, but only one side has the physical connections.

CommandExplanation
interface vlan <n>Creates a Switched Virtual Interface (SVI) — the layer-3 gateway for that VLAN. Devices in the VLAN use this IP as their default gateway. Equivalent to Cisco's interface vlan <n>.
vsx-sync active-gatewaysSynchronizes the active-gateway configuration to the VSX peer. This ensures both switches have the same virtual gateway IP, so failover is seamless.
ip address 10.0.2.42/24The real IP of this SVI on ND4-prim. Used for management, OSPF adjacencies, and as a source IP for traffic originating from this switch. ND4-sec would have 10.0.2.43/24.
active-gateway ip mac 02:02:00:04:41:01Sets the virtual MAC address for the active-gateway. This is a custom MAC (not auto-generated) that both VSX peers share. When either switch responds to ARP for the virtual IP, it uses this MAC. The 02 prefix indicates a locally administered address.

Why custom MAC? Consistent MAC across failover events prevents ARP cache thrashing on endpoints.
active-gateway ip 10.0.2.41The virtual IP address that serves as the default gateway for devices in this VLAN. This is Aruba's equivalent of VRRP/HSRP virtual IP.

• Devices use 10.0.2.41 as their gateway (not .42 or .43)
• ND4-prim (primary) responds to ARP and forwards traffic
• If ND4-prim fails, ND4-sec takes over instantly with the same IP and MAC
• No election, no timers, no failover delay — this is faster than VRRP
ip helper-address 10.0.10.12
(×3 servers)		DHCP relay (IP helper). When a device in VLAN 124 broadcasts a DHCP Discover, the switch forwards it as a unicast to these DHCP servers. Three servers (10.0.10.12, .13, .14) provide redundancy. The switch adds a Relay Agent Information Option (Option 82) with the VLAN and switch info so the DHCP server knows which subnet/pool to assign an IP from.

💡
Active-Gateway vs VRRP: Aruba's active-gateway is VSX-native and provides sub-second failover because both peers already share the MAC/IP — there's no election process. VRRP has a 3-second default election timer. Active-gateway is only available within a VSX pair, while VRRP works between any vendors.

🏗️ Architecture Summary — What We Learned

  • Access Layer (ND2-E204): Simple ArubaOS-Switch. Creates VLANs, assigns access ports, uplinks via LACP trunk. No routing, no HA. Keeps it simple and reliable at the edge.
  • Distribution/Core (ND4-prim): Complex ArubaOS-CX. VSX pair for HA, 47 MCLAGs to access switches, inter-VLAN routing via OSPF, active-gateway for sub-second failover, DHCP relay, sFlow monitoring, centralized logging.
  • VSX provides: Active-active forwarding (not active-standby), MCLAG for multi-chassis link aggregation, active-gateway replacing VRRP with faster failover, ISL for state sync, dedicated keepalive for split-brain prevention.
  • Two different Aruba OSes coexist: ArubaOS-Switch (ProVision) on access switches — simple, mature, CLI风格 like legacy HP. ArubaOS-CX on distribution/core — modern, Linux-based, Cisco-like CLI, REST API, VSX.
  • Native VLAN 244 serves as the management channel between distribution and access. All other VLANs are tagged on MCLAG trunks.
  • OSPF Area 0 with redistribute connected+static — simple single-area design that advertises all VLAN subnets to the firewall.
  • Three DHCP servers (10.0.10.12/13/14) provide redundancy for IP address assignment across all user VLANs.
