Part 1 — ND1-E101 (Access Switch) 24 Ethernet ports + 2 Gigabit uplinks · Comware v5.20

1
Set Hostname & Super Password
Name the switch for identification and set a privileged (Level 3) password to protect admin access.
ND1-E101 — ACCESS SWITCH
<ND1-E101> system-view
! Enter system view (global config mode)

[ND1-E101] sysname ND1-E101
! Set the switch hostname to ND1-E101
! This name appears in CLI prompts and logs

[ND1-E101] super password level 3 cipher YourStrongPass123
! Set Level 3 (management) super password
! 'cipher' stores it encrypted in running-config
! Used when elevating from lower privilege levels
ℹ️
Comware Privilege Levels: Level 0 = Visit, Level 1 = Monitor, Level 2 = Configuration, Level 3 = Management (full admin). Always set a super password for Level 3.
2
Enable Telnet & SSH Server
Activate remote management protocols so administrators can access the switch without a console cable.
ND1-E101 — ACCESS SWITCH
[ND1-E101] telnet server enable
! Enable the Telnet server for remote CLI access
! Telnet is unencrypted — use SSH in production

[ND1-E101] ssh server enable
! Enable the SSH server for secure remote access
! Requires RSA/DSA key pair to be generated first

[ND1-E101] ip https enable
! Enable the web-based management interface (HTTPS)
⚠️
Security Note: In a production environment, disable Telnet and use only SSH. Telnet transmits credentials in plain text. Keep it enabled in the lab for learning purposes only.
3
Create VLANs
Create VLAN 50 (bahrya — for user data/access points) and VLAN 241 (management — for switch management IP). Remove unused VLAN 1 from trunk PVID.
ND1-E101 — ACCESS SWITCH
[ND1-E101] vlan 50
[ND1-E101-vlan50] name bahrya
[ND1-E101-vlan50] quit
! Create VLAN 50 and name it "bahrya"
! This VLAN carries user data traffic (APs, devices)

[ND1-E101] vlan 241
[ND1-E101-vlan241] name management
[ND1-E101-vlan241] quit
! Create VLAN 241 for switch management
! All management traffic (SNMP, SSH, web) uses this VLAN

[ND1-E101] voice vlan track lldp
! Enable voice VLAN tracking via LLDP for VoIP phones
! Automatically assigns voice VLAN based on LLDP negotiation
💡
Best Practice: Always name your VLANs descriptively. Run display vlan to verify creation. VLAN 1 exists by default but should not carry user traffic.
4
Configure Local User Accounts
Create two accounts: manager (Level 3 — full admin) and monitor (Level 1 — read-only). Enable scheme-based authentication for VTY lines.
ND1-E101 — ACCESS SWITCH
[ND1-E101] domain system
[ND1-E101-isp-system] access-limit disable
[ND1-E101-isp-system] state active
[ND1-E101-isp-system] idle-cut disable
[ND1-E101-isp-system] self-service-url disable
[ND1-E101-isp-system] quit
! Configure the default "system" domain
! This domain is used for local authentication

[ND1-E101] user-group system
[ND1-E101-ugroup-system] group-attribute allow-guest
[ND1-E101-ugroup-system] quit
! Configure the system user group

! --- MANAGER ACCOUNT (Level 3 - Full Admin) ---
[ND1-E101] local-user manager
[ND1-E101-luser-manager] password cipher ManagerPass123!
[ND1-E101-luser-manager] authorization-attribute level 3
[ND1-E101-luser-manager] service-type ssh telnet
[ND1-E101-luser-manager] service-type web
[ND1-E101-luser-manager] quit
! Create "manager" user with Level 3 (full admin) privileges
! Allowed services: SSH, Telnet, and Web management

! --- MONITOR ACCOUNT (Level 1 - Read Only) ---
[ND1-E101] local-user monitor
[ND1-E101-luser-monitor] password cipher MonitorPass123!
[ND1-E101-luser-monitor] authorization-attribute level 1
[ND1-E101-luser-monitor] service-type ssh telnet
[ND1-E101-luser-monitor] service-type web
[ND1-E101-luser-monitor] quit
! Create "monitor" user with Level 1 (read-only) privileges
! Can view configs but cannot modify them
AccountLevelAccessUse Case
manager3 (Management)SSH, Telnet, WebFull configuration access
monitor1 (Monitor)SSH, Telnet, WebRead-only / troubleshooting
5
Configure Management VLAN Interface (SVI)
Assign IP address 10.0.241.11/24 to VLAN 241 interface. This is the switch's management IP for SSH, SNMP, and web access.
ND1-E101 — ACCESS SWITCH
[ND1-E101] interface Vlan-interface241
[ND1-E101-Vlan-interface241] ip address 10.0.241.11 255.255.255.0
[ND1-E101-Vlan-interface241] quit
! Create Layer 3 SVI for VLAN 241
! IP: 10.0.241.11 with /24 subnet mask
! This IP is used for all remote management access
! Make sure at least one port is in VLAN 241 to bring up the SVI
ℹ️
SVI Status: The VLAN interface stays DOWN until at least one physical port in that VLAN is UP. We'll assign port E1/0/24 to VLAN 241 in Step 8 to bring up the management interface.
6
Configure Access Ports — VLAN 50 with PoE & Edge STP
Configure Ethernet 1/0/1 through 1/0/22 as hybrid access ports for VLAN 50 (bahrya). Enable PoE for APs and STP edge port for fast convergence.
⚡ Applied to ports: Ethernet1/0/1, Ethernet1/0/2, Ethernet1/0/3, Ethernet1/0/4, Ethernet1/0/5, Ethernet1/0/6, Ethernet1/0/7, Ethernet1/0/8, Ethernet1/0/9, Ethernet1/0/10, Ethernet1/0/11, Ethernet1/0/12, Ethernet1/0/13, Ethernet1/0/14, Ethernet1/0/15, Ethernet1/0/16, Ethernet1/0/17, Ethernet1/0/18, Ethernet1/0/19, Ethernet1/0/20, Ethernet1/0/21, Ethernet1/0/22
ND1-E101 — ACCESS SWITCH (Example for E1/0/1)
[ND1-E101] interface Ethernet1/0/1
[ND1-E101-Ethernet1/0/1] port link-type hybrid
! Set port to hybrid mode (Comware's flexible port type)
! Hybrid can tag some VLANs and untag others

[ND1-E101-Ethernet1/0/1] undo port hybrid vlan 1
! Remove VLAN 1 from the hybrid allowed list
! Security best practice — don't leak traffic to default VLAN

[ND1-E101-Ethernet1/0/1] port hybrid vlan 50 untagged
! Add VLAN 50 as untagged — connected device sees no VLAN tag
! This makes it behave like an access port for VLAN 50

[ND1-E101-Ethernet1/0/1] port hybrid pvid vlan 50
! Set the Port VLAN ID (PVID) to 50
! Untagged incoming frames are assigned to VLAN 50

[ND1-E101-Ethernet1/0/1] poe enable
! Enable Power over Ethernet on this port
! Powers connected wireless access points (802.3af/at)

[ND1-E101-Ethernet1/0/1] stp edged-port enable
! Set as STP edge port (same as Cisco PortFast)
! Skips STP listening/learning — goes directly to forwarding
! Prevents 30-50 second delay when device connects

[ND1-E101-Ethernet1/0/1] quit
💡
Repeat for E1/0/2 through E1/0/22: Every access port has the exact same configuration. In production, use port-group or a script to apply to all ports at once. In the simulator, configure each port individually for learning.
ND1-E101 — BULK CONFIG (All 22 ports)
! Repeat this block for ports 2 through 22:
interface Ethernet1/0/2
 port link-type hybrid
 undo port hybrid vlan 1
 port hybrid vlan 50 untagged
 port hybrid pvid vlan 50
 poe enable
 stp edged-port enable
quit

! ... repeat for Ethernet1/0/3 through Ethernet1/0/22
! (Same 6 commands per port)
ℹ️
Why Hybrid not Access? Comware's "hybrid" mode is more flexible than "access". An access port can only belong to one VLAN. A hybrid port can carry multiple VLANs — some tagged, some untagged. Using hybrid with a single untagged VLAN achieves the same result as access mode but gives you room to add a voice VLAN later.
7
Configure Trunk Uplink — Ethernet 1/0/23
Configure E1/0/23 as a trunk port carrying all VLANs to the distribution switch. Set PVID to VLAN 241 (management).
ND1-E101 — ACCESS SWITCH
[ND1-E101] interface Ethernet1/0/23
[ND1-E101-Ethernet1/0/23] port link-type trunk
! Set port to trunk mode — carries multiple tagged VLANs

[ND1-E101-Ethernet1/0/23] port trunk permit vlan all
! Allow ALL VLANs to pass through this trunk
! In production, restrict to only needed VLANs for security

[ND1-E101-Ethernet1/0/23] port trunk pvid vlan 241
! Set native VLAN (PVID) to 241 (management)
! Untagged frames on this trunk are placed in VLAN 241

[ND1-E101-Ethernet1/0/23] quit
8
Configure Management Access Port — Ethernet 1/0/24
Assign E1/0/24 to VLAN 241 as an access port for a directly connected management device. This also brings up the VLAN 241 SVI.
ND1-E101 — ACCESS SWITCH
[ND1-E101] interface Ethernet1/0/24
[ND1-E101-Ethernet1/0/24] description switch-management-port
! Add a description for easy identification

[ND1-E101-Ethernet1/0/24] port access vlan 241
! Set as access port in VLAN 241
! A laptop/NMS connected here gets management access

[ND1-E101-Ethernet1/0/24] stp edged-port enable
! Enable edge port for fast STP convergence

[ND1-E101-Ethernet1/0/24] quit
💡
SVI Activation: After configuring this port, the Vlan-interface241 should come UP. Verify with display ip interface brief. If it's still DOWN, check that the physical link is connected.
9
Configure Link Aggregation Uplink — GE1/0/25 & GE1/0/26
Create a dynamic LAG (Link Aggregation Group 1) using both Gigabit ports for high-bandwidth, redundant uplink to ND6. Enable fiber combo mode.
ND1-E101 — ACCESS SWITCH
! --- Step A: Create the Link Aggregation Group ---
[ND1-E101] interface Bridge-Aggregation1
[ND1-E101-Bridge-Aggregation1] description Connection-to-ND6
[ND1-E101-Bridge-Aggregation1] port link-type trunk
[ND1-E101-Bridge-Aggregation1] port trunk permit vlan all
[ND1-E101-Bridge-Aggregation1] port trunk pvid vlan 241
[ND1-E101-Bridge-Aggregation1] link-aggregation mode dynamic
! Use LACP (dynamic) instead of static mode
! LACP detects misconfigurations and prevents loops
[ND1-E101-Bridge-Aggregation1] quit

! --- Step B: Assign physical ports to the group ---
[ND1-E101] interface GigabitEthernet1/0/25
[ND1-E101-GigabitEthernet1/0/25] port link-type trunk
[ND1-E101-GigabitEthernet1/0/25] port trunk permit vlan all
[ND1-E101-GigabitEthernet1/0/25] port trunk pvid vlan 241
[ND1-E101-GigabitEthernet1/0/25] combo enable fiber
! Switch the combo port to use the SFP fiber interface
! (instead of the copper RJ45)
[ND1-E101-GigabitEthernet1/0/25] port link-aggregation group 1
! Bind this physical port to LAG group 1
[ND1-E101-GigabitEthernet1/0/25] quit

! Repeat for the second member port:
[ND1-E101] interface GigabitEthernet1/0/26
[ND1-E101-GigabitEthernet1/0/26] port link-type trunk
[ND1-E101-GigabitEthernet1/0/26] port trunk permit vlan all
[ND1-E101-GigabitEthernet1/0/26] port trunk pvid vlan 241
[ND1-E101-GigabitEthernet1/0/26] combo enable fiber
[ND1-E101-GigabitEthernet1/0/26] port link-aggregation group 1
[ND1-E101-GigabitEthernet1/0/26] quit
ℹ️
Dynamic vs Static LAG: Dynamic mode uses LACP (IEEE 802.3ad) to negotiate the aggregation. Static mode just bundles ports without negotiation. Always prefer dynamic — if one side is misconfigured, LACP won't form the aggregation, preventing broadcast storms.
10
Configure Default Route
Set a static default route pointing to the distribution switch (10.0.241.1) for all traffic the access switch needs to send off-subnet.
ND1-E101 — ACCESS SWITCH
[ND1-E101] ip route-static 0.0.0.0 0.0.0.0 10.0.241.1
! Default route: send all unknown traffic to 10.0.241.1
! 0.0.0.0/0 = match any destination not in local routing table
! 10.0.241.1 = next-hop (distribution switch or router)
! Needed for: NTP, SNMP traps, firmware downloads, etc.
11
Configure SNMP
Enable SNMP v2c with read-only community "H#@#123" and configure trap destination to the NMS server at 10.0.10.162.
ND1-E101 — ACCESS SWITCH
[ND1-E101] snmp-agent
! Enable the SNMP agent process

[ND1-E101] snmp-agent sys-info version all
! Enable all SNMP versions (v1, v2c, v3)

[ND1-E101] snmp-agent community read H#@#123
! Set read-only community string for SNMP v2c
! NMS can poll switch status but cannot modify config

[ND1-E101] snmp-agent log all
! Enable SNMP logging for all operations

[ND1-E101] snmp-agent target-host trap address udp-domain 10.0.10.162 params securityname H#@#123 v2c
! Configure SNMP trap destination (NMS server)
! Traps are unsolicited notifications (alerts, errors)
! Sent via UDP to 10.0.10.162 using v2c with community "H#@#123"

[ND1-E101] snmp-agent trap enable default-route
! Enable default-route change traps

[ND1-E101] snmp-agent trap queue-size 500
! Set trap queue size to 500 messages

[ND1-E101] snmp-agent trap life 600
! Set trap message lifetime to 600 seconds
! If trap can't be sent within 600s, it's discarded
⚠️
Security Note: SNMP v2c uses plain-text community strings — anyone who knows "H#@#123" can read your switch data. In production, use SNMP v3 with authentication and encryption. The distribution switch (ND1) shows v3 configuration in Part 2.
12
Configure VTY Lines & Password Recovery
Set all 16 VTY lines (0-15) to use scheme authentication (username/password login) and enable password recovery as a safety net.
ND1-E101 — ACCESS SWITCH
[ND1-E101] password-recovery enable
! Allow password recovery via boot menu
! If you lose the password, you can boot and reset it
! Disable in high-security environments

[ND1-E101] user-interface vty 0 15
[ND1-E101-ui-vty0-15] authentication-mode scheme
! Use "scheme" = username + password authentication
! This uses the local-user accounts (manager / monitor)
! Alternative: "password" = simple password only (less secure)

[ND1-E101-ui-vty0-15] protocol inbound telnet
! Allow only Telnet inbound on VTY lines
! Use "protocol inbound ssh" for SSH-only access
! Use "protocol inbound all" for both

[ND1-E101-ui-vty0-15] quit

! --- SAVE CONFIGURATION ---
[ND1-E101] return
<ND1-E101> save
! Save running-config to startup-config
! Without this, all changes are lost on reboot!
💡
Always save! HP Comware does NOT auto-save. Run save after every configuration session. Verify with display current-configuration.

Part 2 — ND1 (Distribution Switch) Multiple modules · IRF · OSPF · sFlow · SNMP v3

13
Configure Trunk Downlink Ports — Module 1 (GE1/0/4 to GE1/0/23)
Configure 20 Gigabit ports as trunks with individual LAG groups for connections to access switches. Each port gets its own LAG for future expansion.
🔗 Applied to ports: GE1/0/4 through GE1/0/23 — each port is a separate trunk assigned to its own LAG group (LAG 4 through LAG 23). GE1/0/24 is in LAG 24 but is shutdown.
ND1 — DISTRIBUTION SWITCH (Example: GE1/0/4)
[ND1] interface GigabitEthernet1/0/4
[ND1-GigabitEthernet1/0/4] port link-mode bridge
! Explicitly set to Layer 2 bridge mode
! (Some Comware switches default to route mode)

[ND1-GigabitEthernet1/0/4] port link-type trunk
[ND1-GigabitEthernet1/0/4] port trunk permit vlan all
[ND1-GigabitEthernet1/0/4] port trunk pvid vlan 241
! Trunk carrying all VLANs, native VLAN = 241 (management)

[ND1-GigabitEthernet1/0/4] port link-aggregation group 4
! Assign to LAG group 4
! Each port has its own LAG for 1:1 access switch mapping

[ND1-GigabitEthernet1/0/4] quit
ND1 — BULK (Remaining ports)
! Repeat for GE1/0/5 through GE1/0/23 (same pattern):
interface GigabitEthernet1/0/5
 port link-mode bridge
 port link-type trunk
 port trunk permit vlan all
 port trunk pvid vlan 241
 port link-aggregation group 5
quit

! GE1/0/6 → LAG 6, GE1/0/7 → LAG 7 ... GE1/0/23 → LAG 23

! --- GE1/0/24: SHUTDOWN (reserved) ---
interface GigabitEthernet1/0/24
 port link-mode bridge
 port link-type trunk
 port trunk permit vlan all
 port trunk pvid vlan 241
 shutdown
! Port is administratively disabled — reserved for future use
 port link-aggregation group 24
quit

! --- GE1/0/25 to GE1/0/31: SHUTDOWN ---
! All shutdown — unused ports
interface GigabitEthernet1/0/25
 port link-mode bridge
 shutdown
quit
! ... repeat for GE1/0/26 through GE1/0/31

! --- GE1/0/32: Management access port ---
interface GigabitEthernet1/0/32
 port link-mode bridge
 port access vlan 241
! Direct management connection in VLAN 241
quit
14
Configure Trunk Ports with sFlow Monitoring — Module 2
Module 2 ports carry trunk traffic AND have sFlow sampling enabled for network traffic analysis. Some ports have flow sampling, others only counter sampling.
ND1 — DISTRIBUTION (GE2/0/1 with sFlow — LAG 1)
[ND1] interface GigabitEthernet2/0/1
[ND1-GigabitEthernet2/0/1] port link-mode bridge
[ND1-GigabitEthernet2/0/1] port link-type trunk
[ND1-GigabitEthernet2/0/1] port trunk permit vlan all
[ND1-GigabitEthernet2/0/1] port trunk pvid vlan 241

! --- sFlow Configuration on this port ---
[ND1-GigabitEthernet2/0/1] sflow flow collector 1
! Send flow samples to collector 1 (defined globally)
[ND1-GigabitEthernet2/0/1] sflow counter interval 30
! Send interface counter data every 30 seconds
[ND1-GigabitEthernet2/0/1] sflow counter collector 1
! Send counter samples to collector 1

[ND1-GigabitEthernet2/0/1] port link-aggregation group 1
[ND1-GigabitEthernet2/0/1] quit
ND1 — WITH FLOW SAMPLING (GE2/0/2 — LAG 2)
[ND1] interface GigabitEthernet2/0/2
[ND1-GigabitEthernet2/0/2] port link-mode bridge
[ND1-GigabitEthernet2/0/2] port link-type trunk
[ND1-GigabitEthernet2/0/2] port trunk permit vlan all
[ND1-GigabitEthernet2/0/2] port trunk pvid vlan 241

! --- sFlow with BOTH flow and counter sampling ---
[ND1-GigabitEthernet2/0/2] sflow sampling-rate 1000
! Sample 1 out of every 1000 packets for flow analysis
! Lower rate = more accurate but more CPU/load
[ND1-GigabitEthernet2/0/2] sflow flow collector 1
[ND1-GigabitEthernet2/0/2] sflow counter interval 30
[ND1-GigabitEthernet2/0/2] sflow counter collector 1

[ND1-GigabitEthernet2/0/2] port link-aggregation group 2
[ND1-GigabitEthernet2/0/2] quit
ℹ️
sFlow vs NetFlow: sFlow (sampled flow) sends statistical samples — lightweight and scalable. NetFlow/IPFIX sends records for every flow — more accurate but heavier. sFlow is preferred on high-throughput distribution switches. The collector at 10.0.10.76 receives all sFlow data (defined globally in Step 2.8).
📊 Module 2 Port Summary:
• GE2/0/1 → LAG 1 (counter only)  • GE2/0/2 → LAG 2 (flow + counter)
• GE2/0/3 → LAG 3 (flow + counter)  • GE2/0/4 → LAG 4 (flow + counter)
• GE2/0/5 → LAG 5 (no sFlow)  • GE2/0/6~8 → LAG 6~8 (flow + counter)
• GE2/0/9 → No LAG  • GE2/0/10 → LAG 19 (counter only — note: different number!)
• GE2/0/11~21 → LAG 11~21 (flow + counter)  • GE2/0/22 → Shutdown
• GE2/0/23 → No LAG  • GE2/0/24 → LAG 24 (flow + counter)
15
Configure Ten-Gigabit Core Uplinks — LAG 41
Four Ten-Gigabit ports form LAG 41 for the high-bandwidth uplink to the core router. Only VLAN 11 is permitted (not all VLANs).
ND1 — DISTRIBUTION (4 × TenGE ports → LAG 41)
! All 4 ports use the same config — example for TenGE1/1/2:
[ND1] interface Ten-GigabitEthernet1/1/2
[ND1-Ten-GigabitEthernet1/1/2] port link-mode bridge
[ND1-Ten-GigabitEthernet1/1/2] port link-type trunk

[ND1-Ten-GigabitEthernet1/1/2] undo port trunk permit vlan 1
! Explicitly remove VLAN 1 from this trunk
! More secure than "permit vlan all"

[ND1-Ten-GigabitEthernet1/1/2] port trunk permit vlan 11
! Only allow VLAN 11 on this uplink
! VLAN 11 = dedicated uplink VLAN to core

[ND1-Ten-GigabitEthernet1/1/2] port trunk pvid vlan 11
! Native VLAN = 11

[ND1-Ten-GigabitEthernet1/1/2] port link-aggregation group 41
[ND1-Ten-GigabitEthernet1/1/2] quit

! Repeat for the other 3 TenGE ports:
interface Ten-GigabitEthernet1/2/2
 port link-mode bridge
 port link-type trunk
 undo port trunk permit vlan 1
 port trunk permit vlan 11
 port trunk pvid vlan 11
 port link-aggregation group 41
quit

interface Ten-GigabitEthernet2/1/2
 port link-mode bridge
 port link-type trunk
 undo port trunk permit vlan 1
 port trunk permit vlan 11
 port trunk pvid vlan 11
 port link-aggregation group 41
quit

Configure OSPF Routing
Enable OSPF process 1 in Area 0. Advertise the uplink subnet (10.0.11.0/24) and import direct routes and static routes into OSPF.
ND1 — DISTRIBUTION — OSPF
[ND1] ospf 1
! Create OSPF process 1

[ND1-ospf-1] import-route direct
! Redistribute directly connected subnets into OSPF
! This advertises all local VLAN interfaces

[ND1-ospf-1] import-route static
! Redistribute static routes into OSPF
! The default route will be advertised to OSPF neighbors

[ND1-ospf-1] area 0.0.0.0
! Enter OSPF Area 0 (backbone area)

[ND1-ospf-1-area-0.0.0.0] network 10.0.11.0 0.0.0.255
! Advertise the 10.0.11.0/24 subnet in Area 0
! This is the uplink VLAN 11 subnet
! Wildcard mask: 0.0.0.255 = inverse of /24

[ND1-ospf-1-area-0.0.0.0] quit
[ND1-ospf-1] quit
ℹ️
OSPF Area Design: The distribution switch is in Area 0 (backbone). Access switches use static routes and don't run OSPF — they're Layer 2 only. The core router is also in Area 0. In larger networks, access switches would be in stub areas or use passive interfaces.

Configure sFlow Agent Globally
Define the sFlow agent IP and collector. This is the global config that the per-port sFlow commands (Step 14) reference.
ND1 — DISTRIBUTION — sFlow GLOBAL
[ND1] sflow agent ip 10.0.241.1
! Set the sFlow agent IP address
! This IP identifies the switch in sFlow datagrams
! Must be a local interface IP (VLAN 241 in this case)

[ND1] sflow collector 1 ip 10.0.10.76 description 6343
! Define collector 1:
!   IP: 10.0.10.76 (sFlow analyzer server)
!   Description: "6343" (default sFlow UDP port)
! All ports referencing "collector 1" send data here
! Typical sFlow tools: InMon, ntopng, PRTG, SolarWinds
ℹ️
sFlow Architecture: The agent (switch) samples packets on interfaces → sends sFlow datagrams via UDP port 6343 → to the collector (analyzer). The collector reconstructs traffic patterns. Sampling rate 1:1000 means 0.1% of packets are sampled — minimal performance impact.

Configure IRF (Intelligent Resilient Framework)
Configure IRF to virtualize two physical switch modules into one logical switch. Uses Ten-Gigabit ports 1/1/1, 1/2/1, 2/1/1, and 2/2/1 as IRF physical links.
ND1 — DISTRIBUTION — IRF CONFIGURATION
! ====================================================
! IRF = Intelligent Resilient Framework
! Combines multiple physical switches into ONE logical switch
! Benefits: unified management, cross-chassis link aggregation,
!          high availability, no STP between chassis
! ====================================================

! --- IRF Port 1/1 (on IRF Member 1) ---
[ND1] irf-port 1/1
! "1/1" = IRF member 1, IRF port 1
[ND1-irf-port1/1] port group interface Ten-GigabitEthernet1/1/1 mode normal
! Bind TenGE1/1/1 as IRF physical link
! "mode normal" = standard IRF link
[ND1-irf-port1/1] quit

! --- IRF Port 1/2 (on IRF Member 1) ---
[ND1] irf-port 1/2
[ND1-irf-port1/2] port group interface Ten-GigabitEthernet1/2/1 mode normal
[ND1-irf-port1/2] quit

! --- IRF Port 2/1 (on IRF Member 2) ---
[ND1] irf-port 2/1
[ND1-irf-port2/1] port group interface Ten-GigabitEthernet2/1/1 mode normal
[ND1-irf-port2/1] quit

! --- IRF Port 2/2 (on IRF Member 2) ---
[ND1] irf-port 2/2
[ND1-irf-port2/2] port group interface Ten-GigabitEthernet2/2/1 mode normal
[ND1-irf-port2/2] quit

! --- ACTIVATE IRF (requires reboot) ---
[ND1] irf configuration active
! Activate the IRF configuration
! ⚠️ This triggers a reboot!
! Both chassis will reboot and form the IRF fabric
! After reboot, they appear as ONE switch

! --- SAVE AND REBOOT ---
[ND1] return
<ND1> save
<ND1> reboot
⚠️
CRITICAL — IRF Activation Causes Reboot! After irf configuration active, both chassis reboot. Make sure: (1) IRF member priorities are set correctly, (2) IRF domain IDs match, (3) Physical IRF links are connected BEFORE activation, (4) You have console access in case of issues.
ℹ️
IRF Topology in This Config: Member 1 has 2 IRF links (TenGE1/1/1 + TenGE1/2/1) and Member 2 has 2 IRF links (TenGE2/1/1 + TenGE2/2/1). This creates a mesh with 4 physical links — if any link fails, the IRF fabric stays connected. The data uplinks (TenGE x/1/2 and x/2/2) are in LAG 41 and carry regular traffic.
