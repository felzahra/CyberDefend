ASA Firewall

Configure a Cisco ASA Firewall using Security Levels, Object NAT, ACLs, Site-to-Site VPNs, and Modular Policy Framework (MPF).

Step 01

Interfaces & Security Levels

ASA firewalls use Security Levels (0-100). Inside is 100 (most trusted), Outside is 0 (least trusted). Traffic from a higher to a lower security level is permitted by default; lower to higher requires an ACL.

Basic Interface Setup

Assign names and security levels to physical interfaces. Ensure you enable them with no shutdown.

asa-interfaces.conf
! Configure Outside Interface (Connected to ISP) ciscoasa(config)# interface gigabitEthernet 0/0 ciscoasa(config-if)# nameif outside ciscoasa(config-if)# security-level 0 ciscoasa(config-if)# ip address 203.0.113.2 255.255.255.0 ciscoasa(config-if)# no shutdown ! Configure Inside Interface (Connected to LAN) ciscoasa(config)# interface gigabitEthernet 0/1 ciscoasa(config-if)# nameif inside ciscoasa(config-if)# security-level 100 ciscoasa(config-if)# ip address 192.168.1.1 255.255.255.0 ciscoasa(config-if)# no shutdown

Step 02

Object NAT (PAT & Static)

Modern ASA uses "Network Objects" for NAT. This makes configurations much cleaner. We will configure Dynamic PAT (Overload) for outbound internet, and Static NAT for an internal Web Server.

Dynamic PAT (Internet Access)

Translate the entire inside LAN to the ASA's Outside IP address.

asa-pat.conf
! 1. Create Network Object for the LAN Subnet ciscoasa(config)# object network LAN_SUBNET ciscoasa(config-network-object)# subnet 192.168.1.0 255.255.255.0 ! 2. Configure Dynamic PAT using the Outside Interface IP ciscoasa(config-network-object)# nat (inside,outside) dynamic interface

Static NAT (Port Forwarding)

Expose an internal Web Server (TCP 80) to the public internet using a dedicated public IP.

asa-static-nat.conf
! 1. Create Network Object for the Web Server ciscoasa(config)# object network WEB_SERVER ciscoasa(config-network-object)# host 192.168.1.10 ! 2. Configure Static NAT (Port Forward TCP 80) ciscoasa(config-network-object)# nat (inside,outside) static 203.0.113.10 service tcp 80 80
Step 03

Access Control Lists (ACLs)

Because traffic from Outside (Security 0) to Inside (Security 100) is denied by default, we must apply an inbound ACL on the Outside interface to allow traffic to the Web Server.

asa-acl.conf
! 1. Create ACL allowing HTTP (80) traffic to the Public IP ciscoasa(config)# access-list OUTSIDE_IN extended permit tcp any host 203.0.113.10 eq 80 ! 2. Allow ICMP (Ping) for testing ciscoasa(config)# access-list OUTSIDE_IN extended permit icmp any any ! 3. Apply the ACL to the Outside interface (Inbound direction) ciscoasa(config)# access-group OUTSIDE_IN in interface outside

Step 04

Site-to-Site IPsec VPN

Configure a secure tunnel between two sites over the internet. Phase 1 (ISAKMP/IKEv1) authenticates peers; Phase 2 (IPsec) encrypts the data.

Phase 1 & 2 Configuration

Define the interesting traffic (ACL), create the transform set, and tie it all together with a Crypto Map applied to the Outside interface.

asa-vpn.conf
! 1. Enable ISAKMP (IKEv1) on Outside interface ciscoasa(config)# crypto ikev1 enable outside ciscoasa(config)# crypto ikev1 policy 10 ciscoasa(config-ikev1-policy)# authentication pre-share ciscoasa(config-ikev1-policy)# encryption aes-256 ciscoasa(config-ikev1-policy)# hash sha ciscoasa(config-ikev1-policy)# group 2 ciscoasa(config-ikev1-policy)# exit ! 2. Define Interesting Traffic (Local LAN to Remote LAN) ciscoasa(config)# access-list VPN_TRAFFIC extended permit ip 192.168.1.0 255.255.255.0 10.0.0.0 255.255.255.0 ! 3. Create Transform Set (Encryption/Hash for Data) ciscoasa(config)# crypto ipsec ikev1 transform-set ESP-AES-SHA esp-aes esp-sha-hmac ! 4. Create Tunnel Group (Peer IP & Pre-Shared Key) ciscoasa(config)# tunnel-group 203.0.113.20 type ipsec-l2l ciscoasa(config-tunnel-general)# ikev1 pre-shared-key MySecretVPNKey123! ! 5. Bind everything together in a Crypto Map ciscoasa(config)# crypto map MY_MAP 10 set peer 203.0.113.20 ciscoasa(config)# crypto map MY_MAP 10 set ikev1 transform-set ESP-AES-SHA ciscoasa(config)# crypto map MY_MAP 10 match address VPN_TRAFFIC ! 6. Apply Crypto Map to Outside interface ciscoasa(config)# crypto map MY_MAP interface outside
Step 05

MPF & Application Inspection

The Modular Policy Framework (MPF) allows the ASA to inspect application layer traffic. This is crucial for protocols like FTP that open secondary data channels dynamically.

Enabling FTP & ICMP Inspection

asa-mpf.conf
! 1. Create Class Map to match default inspection traffic ciscoasa(config)# class-map inspection_default ciscoasa(config-cmap)# match default-inspection-traffic ciscoasa(config-cmap)# exit ! 2. Create Policy Map and apply inspections ciscoasa(config)# policy-map global_policy ciscoasa(config-pmap)# class inspection_default ciscoasa(config-pmap-c)# inspect ftp ciscoasa(config-pmap-c)# inspect icmp ciscoasa(config-pmap-c)# exit ! 3. Apply Policy Map globally ciscoasa(config)# service-policy global_policy global
