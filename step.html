ND2-E204 — Access Switch ArubaOS-Switch (ProVision) · JL258A / Aruba 2540 · 10-Port

ℹ️
This is a layer-2 access switch running ArubaOS-Switch (formerly ProVision). It sits at the building floor level, connects end-user devices, and uplinks to the distribution core via a single LACP trunk. The model JL258A is an Aruba 2540-24G-PoE switch.

LACP Trunk to Distribution
LINK AGGREGATION
TRUNK
trunk 9-10 trk1 lacp
CommandWhat It Does
trunk 9-10 trk1 lacpBundles physical ports 9 and 10 into a single logical trunk called Trk1 using the LACP (802.3ad) protocol.

• 9-10 = port range (SFP uplink ports on the 2540)
• trk1 = the trunk group name (like Cisco's port-channel 1)
• lacp = enables LACP negotiation (active by default in ProVision)

This provides 2 Gbps bandwidth and redundancy — if one SFP link fails, traffic continues on the other. The other end (ND4-prim) has the matching MCLAG configuration.
💡
Cisco vs ArubaOS-Switch trunk:
• Cisco: interface range gi0/1-2 → channel-group 1 mode active
• ArubaOS-Switch: trunk 9-10 trk1 lacp (one line!)
3
Default Route
ROUTING
STATIC ROUTE
ip route 0.0.0.0 0.0.0.0 10.0.242.1
CommandWhat It Does
ip route 0.0.0.0 0.0.0.0 10.0.242.1Sets a default static route (gateway of last resort). All traffic not matching a more specific route is sent to 10.0.242.1.

This is the Distribution switch's SVI IP on VLAN 242 (Managment-Switch). The access switch uses this to reach the management network, NTP servers, syslog, etc.

• Syntax is identical to Cisco IOS
• The access switch needs this because it has an IP on VLAN 242 but doesn't run a routing protocol
⚠️
Why does an L2 switch need a route? ArubaOS-Switch (ProVision) supports basic layer-3 static routing even on "access" switches. This route is used for out-of-band management traffic originating from the switch itself (SNMP traps, syslog, NTP, firmware downloads).

MONITORING
SNMP

CommandWhat It Does
snmp-server community "public"Enables SNMPv1/v2c with the community string "public" for read-only access. This allows monitoring tools (like Zabbix, PRTG, or SolarWinds) to poll the switch for interface stats, CPU, memory, port status, etc.

⚠ Security note: "public" is a well-known default community string. In production, this should be changed to a unique, complex string. SNMPv3 with authentication and encryption is preferred.

VLAN 1 — Default VLAN

CommandExplanation
name "DEFAULT_VLAN"Assigns a human-readable name. VLAN 1 exists by default on all ArubaOS-Switch ports.
no untagged 1-8,Trk1Removes ports 1-8 and Trk1 from the untagged (access) membership of VLAN 1. By default, all ports are untagged in VLAN 1. This command "frees" those ports so they can be assigned to other VLANs. Without this, you can't make ports 1-8 untagged in VLAN 98.
ip address dhcp-bootpConfigures the VLAN 1 SVI to obtain its IP via DHCP or BOOTP. This is the switch's management IP if no other VLAN has a static IP. In this network, it's a fallback — the real management IP is on VLAN 242.
ipv6 enableEnables IPv6 processing on this VLAN interface.
ipv6 address dhcp fullObtains a full IPv6 address via DHCPv6 (not just SLAAC). The switch gets its IPv6 address, DNS, and other options from a DHCPv6 server.

VLAN 98 — Data VLAN (User Ports)

CommandExplanation
untagged 1-8Assigns ports 1 through 8 as untagged (access) members of VLAN 98. Devices plugged into these ports send/receive untagged Ethernet frames — the switch automatically adds/removes the VLAN 98 tag internally. This is equivalent to Cisco's switchport access vlan 98.
tagged Trk1Makes Trk1 a tagged member of VLAN 98. Frames going out Trk1 toward the distribution switch carry an 802.1Q tag with VLAN ID 98. This is how the distribution switch knows which VLAN the traffic belongs to. Equivalent to Cisco's switchport trunk allowed vlan add 98.
no ip addressExplicitly removes any IP address from the VLAN 98 SVI. This switch doesn't need to route for VLAN 98 — the distribution core handles inter-VLAN routing.

VLAN 242 — Switch Management

CommandExplanation
untagged Trk1Trk1 is an untagged member of VLAN 242. This means management traffic between this switch and the distribution core on VLAN 242 flows without 802.1Q tags on this trunk.

⚠ Important: In ArubaOS-Switch, a port can only be untagged in ONE VLAN. Since Trk1 is untagged in VLAN 242, all other VLANs (like 98) must be tagged on Trk1. VLAN 242 acts as the "native VLAN" for this trunk.
ip address 10.0.242.14 255.255.255.0Assigns 10.0.242.14/24 as the switch's management IP address. This is how network admins SSH, SNMP-poll, or web-manage this switch. The gateway is 10.0.242.1 (set in the default route above), which is the distribution switch's VLAN 242 SVI.
📌
Access Switch Port Map Summary:
• Ports 1-8: Access ports, untagged VLAN 98 (user data)
• Ports 9-10: SFP uplinks, bundled as Trk1 (LACP)
• Trk1 untagged: VLAN 242 (management/native)
• Trk1 tagged: VLAN 98 (data)

Spanning Tree Priority
LOOP PREVENTION
STP
spanning-tree Trk1 priority 4
CommandWhat It Does
spanning-tree Trk1 priority 4Sets the Spanning Tree port priority of Trk1 to 4 (default is 8). Lower value = higher priority = more likely to become the root port (the port that forwards traffic toward the root bridge).

Since this access switch has only one uplink (Trk1), this setting mainly matters if there were redundant uplinks — it ensures Trk1 is preferred over any other path. The priority value is multiplied by 4096 internally (4 × 4096 = 16384 in the actual BPDU).

Transceiver & Password
HARDWARE / SECURITY
MISC
allow-unsupported-transceiver
password manager
CommandWhat It Does
allow-unsupported-transceiverAllows the use of third-party / non-HPE SFP/SFP+ transceivers. By default, Aruba switches reject non-certified optics and show a warning. This command bypasses that check. Common when using cheaper or specialty optics (like long-range BiDi SFPs) that aren't on HPE's compatibility list.

⚠ Risk: Unsupported transceivers may cause intermittent issues and are not covered by HPE support.
password managerPrompts to set or change the manager-level password. In ArubaOS-Switch there are two privilege levels:
• Operator — read-only access (like Cisco's enable level 1)
• Manager — full read-write access (like Cisco's enable level 15)

The actual password hash is not shown in display current-configuration for security — it's stored separately.
✅
ND2-E204 Access Switch — Complete! This is a minimal, clean access switch config. It does exactly what an access switch should: assign user ports to a data VLAN, uplink to distribution via LACP, and have a management IP for monitoring. No routing protocols, no complex policies — keep it simple at the edge.

ND4-prim — Distribution Core Switch ArubaOS-CX GL.10.07.0004 · VSX Primary · 6400/8320 Series

ℹ️
This is the primary distribution/core switch in a VSX (Virtual Switching Extension) pair. It runs ArubaOS-CX — a modern, Linux-based OS. It handles inter-VLAN routing (OSPF), VSX high-availability, 47 MCLAG downlinks to access switches, active-gateway (like VRRP), DHCP relay, sFlow monitoring, and more. This is the brain of the network.

CommandExplanation
spanning-tree mode rpvstSets the spanning tree mode to RPVST (Rapid Per-VLAN Spanning Tree). This is the ArubaOS-CX equivalent of Cisco's spanning-tree mode rapid-pvst.

VSX DOWNLINKS
MCLAG TEMPLATE (lag 1-47)
interface lag 1 multi-chassis
    vsx-sync vlans
    no shutdown
    no routing
    vlan trunk native 244
    vlan trunk allowed all
    lacp mode active
CommandExplanation
interface lag <n> multi-chassisCreates a Multi-Chassis LAG (MCLAG). Unlike a regular LAG that bundles ports on a single switch, an MCLAG spans two physical switches (ND4-prim + ND4-sec). The access switch sees both distribution switches as a single logical device.
vsx-sync vlansSynchronizes this LAG's VLAN configuration to the VSX peer.
no routingDisables IP routing on this LAG — it's a pure layer-2 trunk.
vlan trunk native 244Sets VLAN 244 as the native (untagged) VLAN on this trunk.
vlan trunk allowed allAllows all VLANs on this trunk.
lacp mode activeEnables LACP in active mode. The switch actively sends LACPDU frames to negotiate the link aggregation.

VSX Keepalive Link (Dedicated)
VSX HEARTBEAT
KEEPALIVE PORT
interface 1/1/48
    no shutdown
    description Keepalive-link
    ip address 10.0.4.41/24
CommandExplanation
interface 1/1/48A dedicated physical port used exclusively for the VSX keepalive. This is a layer-3 routed port.
ip address 10.0.4.41/24IP address for keepalive messages. The peer (ND4-sec) uses 10.0.4.42 on its keepalive port.
⚠️
Why a separate keepalive link? The ISL (lag 128) carries VSX data + control, but if the ISL fails, the switches need an independent path to detect if the peer is truly down. Without it, a split-brain scenario could occur.

SVI EXAMPLES

CommandExplanation
interface vlan <n>Creates a Switched Virtual Interface (SVI) — the layer-3 gateway for that VLAN.
vsx-sync active-gatewaysSynchronizes the active-gateway configuration to the VSX peer.
ip address 10.0.2.42/24The real IP of this SVI on ND4-prim.
active-gateway ip mac 02:02:...Sets the virtual MAC address for the active-gateway that both VSX peers share.
active-gateway ip 10.0.2.41The virtual IP address that serves as the default gateway for devices in this VLAN. Aruba's equivalent of VRRP/HSRP virtual IP. No election, no timers, no failover delay — faster than VRRP.
ip helper-address 10.0.10.12DHCP relay (IP helper). Forwards DHCP broadcasts to DHCP servers as unicast.
ip ospf 1 area 0.0.0.0Enables OSPF on this SVI in Area 0 (backbone area).
💡
Active-Gateway vs VRRP: Aruba's active-gateway is VSX-native and provides sub-second failover because both peers already share the MAC/IP — there's no election process.

🏗️ Architecture Summary — What We Learned

  • Access Layer (ND2-E204): Simple ArubaOS-Switch. Creates VLANs, assigns access ports, uplinks via LACP trunk. No routing, no HA. Keeps it simple and reliable at the edge.
  • Distribution/Core (ND4-prim): Complex ArubaOS-CX. VSX pair for HA, 47 MCLAGs to access switches, inter-VLAN routing via OSPF, active-gateway for sub-second failover, DHCP relay, sFlow monitoring, centralized logging.
  • VSX provides: Active-active forwarding (not active-standby), MCLAG for multi-chassis link aggregation, active-gateway replacing VRRP with faster failover, ISL for state sync, dedicated keepalive for split-brain prevention.
  • Two different Aruba OSes coexist: ArubaOS-Switch (ProVision) on access switches — simple, mature. ArubaOS-CX on distribution/core — modern, Linux-based, Cisco-like CLI, REST API, VSX.
  • Native VLAN 244 serves as the management channel between distribution and access. All other VLANs are tagged on MCLAG trunks.
  • OSPF Area 0 with redistribute connected+static — simple single-area design.
  • Three DHCP servers (10.0.10.12/13/14) provide redundancy for IP address assignment across all user VLANs.
