Command Declarations & Step-by-Step Explanations

FortiGate HA & IP Configuration

1. HA Group & Mode Configuration

config system ha set group-name "FGT-HA" set mode a-a set hbdev "port3" 50 "port4" 50 end

Explanation: This creates the High Availability cluster named "FGT-HA".
- mode a-a: Sets the cluster to Active-Active, meaning both firewalls process traffic simultaneously.
- hbdev: Defines port3 and port4 as Heartbeat interfaces (priority 50). These links are used by the firewalls to check if the other one is alive and to synchronize session tables. They do NOT carry user traffic IPs.

2. Dedicated Management Interface

set ha-mgmt-status enable set ha-mgmt-interface "mgmt1"

Explanation: In an HA cluster, all regular interfaces share the exact same IP addresses (floating IPs). To access each firewall individually for troubleshooting, a dedicated management interface is reserved. This tells the FortiGate to keep mgmt1 out of the HA synchronization, allowing Node 1 to use 10.0.254.101 and Node 2 to use 10.0.254.102.

3. Redundant (Floating) IP Addresses

config system interface edit "port13" set ip 10.0.251.254 255.255.255.0 set alias "inside" next end

Explanation: Because this is an HA cluster, the IP address assigned to the inside interface (port13) acts as a Redundant/Floating IP.
- The Active node currently "owns" this IP and processes the traffic.
- If the Active node fails, the Standby node takes over this exact IP address, ensuring network traffic is uninterrupted. Both firewalls connect down to the Core Switch using this IP.

Juniper SRX Cluster & IP Configuration

1. Chassis Cluster & Redundancy Groups

chassis { cluster { reth-count 10; redundancy-group 0 { node 0 priority 100; node 1 priority 1; } } }

Explanation: This command enables the SRX chassis cluster.
- reth-count 10: Allows up to 10 Redundant Ethernet interfaces.
- redundancy-group 0: Controls the Control Plane (Routing Engine). Node 0 is Primary (100), Node 1 is Backup (1).

2. Dedicated Management IP (fxp0)

groups { node0 { interfaces { fxp0 { unit 0 { family inet { address 10.254.254.1/24; } } } } } }

Explanation: The SRX uses configuration groups to apply specific settings to individual nodes.
- The fxp0 interface is the dedicated physical management port.
- Node 0 is explicitly assigned 10.254.254.1 and Node 1 is assigned 10.254.254.2. These IPs are unique per node and do NOT float, allowing direct SSH access to each chassis.

3. Redundant Ethernet (reth) Floating IPs

interfaces { reth1 { redundant-ether-options { redundancy-group 1; } unit 0 { family inet { address 10.0.251.1/24; } } } }

Explanation: A Redundant Ethernet interface (reth) bundles physical ports from Node 0 and Node 1 into a single virtual interface.
- It connects up to the Core Switch.
- The IP address (e.g., 10.0.251.1) is the Redundant/Floating IP. Whichever node is active for RG1 will use this IP to route traffic. If Node 0 dies, Node 1 takes the IP seamlessly.

Core Switch & Router Connectivity

1. Transit and VLAN Configuration

// Router Configuration interface GigabitEthernet0/0/1 description WAN_LINK ip address 41.33.25.1 255.255.255.128 ! interface GigabitEthernet0/0/2 description TO_CORE_SWITCH ip address 10.0.251.1 255.255.255.0 // Core Switch L3 Configuration interface Vlan251 description TRANSIT_TO_ROUTER ip address 10.0.251.2 255.255.255.0 ! interface Vlan10 description SERVERS_ZONE ip address 10.0.10.1 255.255.255.0 ! interface Vlan100 description DATA_ZONE ip address 172.16.100.1 255.255.255.0

Explanation: Traffic flows logically from the Internet, into the Edge Router, and down into the Core Switch.
- The Core Switch acts as the central backbone. It routes the 10.0.251.0/24 transit network between the Router, the FortiGate (10.0.251.254), and the SRX (10.0.251.1).
- It also holds the SVI (Switch Virtual Interface) IPs for internal zones like the Servers (10.0.10.1) and Data (172.16.100.1), allowing the firewalls to route traffic to these subnets correctly.
