Switch IOS Recovery, TFTP & SCADA Networks

Managing catastrophic switch crashes, recovering IOS images via TFTP, backing up configuration files, and understanding the role of switches in SCADA environments.

1. Switch IOS Crash & Rommon Recovery

A Cisco switch's operating system (IOS - Internetwork Operating System) is stored in flash memory. If the IOS image becomes corrupted, is accidentally deleted, or fails an upgrade, the switch will crash and enter ROMMON mode (ROM Monitor). ROMMON is a low-level diagnostic mode with a basic command set, indicated by the switch: prompt.

To recover from ROMMON, you must connect to the switch physically using a console cable and use the XMODEM protocol or the boot command to pull a new IOS image from a TFTP server.

2. Configuration File Management

A switch's configuration is separate from its OS. The configuration dictates how the ports behave, VLANs, routing, and security. There are two main config files:

  • running-config: The active configuration currently running in the switch's RAM. Changes take effect immediately but are lost on reboot.
  • startup-config: The saved configuration stored in NVRAM. The switch loads this file into RAM when it boots up.

It is critical to back up the startup-config to an external TFTP server before making major changes to the network.

Backup & Restore Commands

# Save running changes to NVRAM
Switch# copy running-config startup-config

# Backup configuration to TFTP Server
Switch# copy startup-config tftp:
Address or name of remote host []? 192.168.1.100
Destination filename [startup-config]? switch-backup-cfg.txt

# Restore configuration from TFTP Server
Switch# copy tftp: running-config
Address or name of remote host []? 192.168.1.100
Source filename []? switch-backup-cfg.txt

3. TFTP Server & IOS Transfers

TFTP (Trivial File Transfer Protocol) is a simple, lightweight protocol used by network admins to transfer IOS images and configuration files. Unlike FTP, TFTP does not require authentication and uses UDP port 69, making it fast for LAN transfers.

Upgrading the IOS Image

To upgrade or replace the IOS, you point the switch to the TFTP server and instruct it to copy the new .bin file into its flash memory.

# Copy new IOS image from TFTP to Switch Flash
Switch# copy tftp: flash:
Address or name of remote host []? 192.168.1.100
Source filename []? c2960-lanbasek9-mz.150-2.SE.bin
Destination filename [c2960-lanbasek9-mz.150-2.SE.bin]? 

# Tell the switch to boot the new image
Switch(config)# boot system flash:c2960-lanbasek9-mz.150-2.SE.bin
Switch# reload

4. SCADA Networks & Daemons

SCADA (Supervisory Control and Data Acquisition) networks are used in Industrial Control Systems (ICS) like power grids, water treatment plants, and manufacturing floors. In these environments, switches must guarantee 99.999% uptime.

A SCADA Daemon is a background process running on industrial servers or routers that continuously polls field devices (PLCs, RTUs) for data. If a switch crashes in a SCADA network, the daemon loses connection to the field devices, potentially causing physical damage or safety hazards. Therefore, SCADA switches are often configured with redundant ring topologies (like Cisco's Resilient Ethernet Protocol - REP) to ensure traffic reroutes in milliseconds if a link goes down.

5. Physical Cabling & Connections

When a switch crashes and network access (in-band management) is lost, you must rely on out-of-band management using physical console cables.

  • Console Cable (RJ45 to USB/Serial): Connects directly from your laptop to the switch's blue console port. Used for ROMMON recovery and initial configuration.
  • rollover Cable: The specific pinout used inside the console cable (Pin 1 to Pin 8, Pin 2 to Pin 7, etc.).
  • Ethernet (RJ45 / Fiber): Used for in-band management, TFTP file transfers, and normal network traffic once the switch is booted and has an IP address.

Transfer Speed Warning

Console port speeds default to 9600 baud (very slow). If you are transferring a 20MB IOS image over a console cable using XMODEM, it can take over 2 hours. Always recover the switch by booting from a TFTP server over an Ethernet cable whenever possible, as it takes only minutes.
