Vulnerability Scanners & Penetration Testing

Understanding the core concepts of vulnerability scanning, the penetration testing lifecycle, and the tools used to identify and exploit weaknesses.

1. Core Concepts

A Vulnerability is a weakness in a system, application, or network that could be exploited by a threat actor. Vulnerability Scanning is the process of identifying these weaknesses automatically. Penetration Testing (Pentesting) goes a step further by actively exploiting those vulnerabilities to determine the real-world impact and verify if the weakness can be compromised.

Vulnerability: A flaw in code or configuration that exposes a system to attack.

Scanning: Automated process of checking systems against a database of known flaws.

Exploitation: The active attempt to breach a system using the discovered vulnerability.

2. The Penetration Testing Cycle

Penetration testing is not just about hacking; it follows a structured methodology (often based on PTES - Penetration Testing Execution Standard) to ensure comprehensive coverage and accurate reporting.

Phase 1: Reconnaissance (Information Gathering)

Gathering as much information as possible about the target (OSINT, DNS, IP ranges) without actively engaging the target's systems.

Phase 2: Scanning & Enumeration

Actively probing the target for open ports, running services, and identifying potential vulnerabilities using tools like Nmap and Nessus.

Phase 3: Exploitation (Gaining Access)

Attempting to leverage the discovered vulnerabilities to gain unauthorized access to the system using frameworks like Metasploit.

Phase 4: Post-Exploitation (Maintaining Access)

Determining the value of the compromised machine, escalating privileges, stealing data, and creating backdoors to maintain access.

Phase 5: Reporting

Documenting the findings, the steps taken to exploit them, the risk level, and remediation recommendations for the client.

3. False Positives & Negatives

Scanners are not perfect. They rely on signatures and heuristics, which can sometimes lead to inaccurate results. Understanding these errors is crucial for a penetration tester.

Scanner Errors

  • False Positive: The scanner reports a vulnerability that does not actually exist. This wastes time as a pentester must manually verify it.
  • False Negative: The scanner fails to detect a real vulnerability. This is highly dangerous as it leaves the system exposed.

4. Types of Vulnerability Scanners

Different scanners are designed to inspect different layers of the technology stack.

  • Network Scanners: Identify open ports and vulnerable services running on network devices (e.g., routers, switches, servers).
  • Web Application Scanners: Look for vulnerabilities in web apps like SQL Injection, XSS, and CSRF by crawling web pages.
  • Host/Infrastructure Scanners: Installed locally on endpoints to check OS patch levels, insecure configurations, and missing updates.
  • Database Scanners: Specialized tools that look for misconfigurations, weak credentials, and vulnerabilities in SQL/NoSQL databases.

5. Top Vulnerability Scanning Tools

The cybersecurity industry relies on a mix of commercial and open-source scanners to get the job done.

Nessus: The industry-standard commercial network vulnerability scanner.

OpenVAS: A powerful open-source alternative to Nessus for network scanning.

OWASP ZAP: Open-source web application scanners for finding XSS, SQLi, and misconfigurations.

Nmap (NSE): Primarily a port scanner, but its Nmap Scripting Engine contains hundreds of vuln-detection scripts.

Reconnaissance & OSINT Tools

The first phase of any cyber attack or security assessment is gathering information. Learn how to use Shodan, theHarvester, DNS_lookup, and Google Dorks to map a target's digital footprint.

Shodan: The Search Engine for the Internet of Things

While Google searches for websites (HTML), Shodan searches for internet-connected devices. It scans the entire internet for open ports, grabbing the "banners" (metadata) returned by services like webcams, routers, servers, and Industrial Control Systems (ICS).

Security professionals use Shodan to find exposed devices on their own networks that they didn't realize were public. Attackers use it to find vulnerable targets (e.g., unpatched web servers or default-password webcams).

Shodan Search Examples

# Find Apache servers in the US
apache country:US

# Find devices running default RDP port (3389) in a specific city
port:3389 city:"New York"

# Find industrial control systems (SCADA) exposed online
port:502

theHarvester: Email and Subdomain Gathering

theHarvester is a built-in Kali Linux tool designed for Open-Source Intelligence (OSINT). It queries multiple search engines (Google, Bing), PGP keys, and social networks to gather emails, subdomains, and employee names associated with a target domain.

This tool is essential for the reconnaissance phase of a penetration test. Finding employee emails allows testers to launch controlled phishing campaigns to test an organization's human firewall.

theHarvester Command Example

theHarvester -d example.com -b google,linkedin -l 500

This command searches Google and LinkedIn for up to 500 results related to the domain example.com.

What is WHOIS?

WHOIS (pronounced "who is") is a query and response protocol widely used for querying databases that store the registered users or assignees of an Internet resource, such as a domain name or an IP address block. It is a fundamental tool for OSINT (Open-Source Intelligence), network troubleshooting, and cybersecurity investigations.

Features of WHOIS

When performing a WHOIS lookup, the protocol returns various pieces of valuable information regarding the domain's registration and infrastructure:

  • Registration Timeline: Provides information on the domain's registration date, expiration date, and last update.
  • Contact Details: Displays names, addresses, phone numbers, and email addresses linked with the domain (Registrant, Admin, and Tech contacts).
  • Nameservers: Lists the nameservers in charge of routing traffic to the domain, which might offer information on the website's hosting provider.
  • Domain Status: Determines if the domain is live, dormant, or marked for possible problems (e.g., pending deletion, serverHold, or transferProhibited).

Pros & Cons of WHOIS

While WHOIS is an essential tool for security and network professionals, it comes with its own set of advantages and disadvantages.

Pros

  • Gives a clearer picture of who is behind a website, potentially aiding accountability.
  • Assists network administrators in resolving technical issues with a domain or website.
  • Helps businesses detect infringement of trademarks and take necessary actions.
  • Can be used to find the responsible parties in cases of phishing scams or the distribution of illegal content.

Cons

  • Exposes contact details of the domain owner, potentially leading to unsolicited emails or spam.
  • Actions taken against parties misusing domains can be difficult, especially when operating across international borders.
  • Registrants may not keep their contact details current, making it hard to reach relevant parties.
  • Domain owners can mask their identifying details through paid privacy protection services, rendering some WHOIS data less useful.

4. Google Dorks (Google Hacking)

Google Dorking or "Google Hacking" is a technique that uses advanced search operators in Google to find specific, hidden, or sensitive information that was accidentally exposed on the internet. This could include passwords, exposed admin panels, or confidential documents.

Common Google Dork Operators

  • site: Restricts results to a specific website (e.g., site:example.com).
  • filetype: Searches for specific file extensions (e.g., filetype:pdf).
  • inurl: Searches for a specific word in the URL (e.g., inurl:admin).
  • intitle: Searches for a specific word in the page title (e.g., intitle:"index of").

Google Dork Examples

# Find exposed password files on a specific domain
site:example.com filetype:txt "password"

# Find open directory listings
intitle:"index of" "parent directory"

# Find exposed phpMyAdmin login pages
inurl:phpmyadmin intitle:"phpMyAdmin"

The Google Hacking Database (GHDB)

Offensive Security maintains the GHDB, a massive collection of Google Dorks used by penetration testers to find exposed data. Defenders should regularly use these dorks against their own domains to ensure they aren't leaking sensitive files.

Bug Bounty Hunting

Learn how ethical hackers legally hack organizations to find vulnerabilities, improve global security, and get paid for their discoveries.

What is a Bug Bounty Program?

A Bug Bounty Program is a deal offered by websites, organizations, and software developers by which individuals can receive recognition and compensation (bounties) for reporting bugs, especially those pertaining to security exploits and vulnerabilities.

Instead of hiring a full-time penetration testing team, companies use bug bounty platforms to crowdsource security testing. This allows thousands of ethical hackers from around the world to continuously test their applications. Famous programs include those run by Google, Microsoft, Apple, and the US Department of Defense.

How Bug Bounties Work

Bug bounty hunting requires a systematic approach. You cannot just start hacking; you must follow the rules set by the organization to ensure you are testing legally and ethically.

The Process

  • 1. Find a Program: Register on a bug bounty platform like HackerOne, Bugcrowd, or Intigriti. Browse the public programs.
  • 2. Read the Scope: The program will define exactly what you are allowed to test (e.g., *.example.com) and what is strictly off-limits (e.g., physical security, social engineering, DDoS attacks).
  • 3. Hunt for Bugs: Use your penetration testing skills (Recon, Scanning, Exploitation) to find vulnerabilities in the scope.
  • 4. Write a Report: Document the vulnerability clearly, including steps to reproduce (PoC) and the potential impact.
  • 5. Get Rewarded: If the bug is valid and not a duplicate (already reported by someone else), you receive a bounty. Payouts range from $50 to $100,000+ depending on the severity.

3. The Bug Bounty Methodology

Top bug bounty hunters don't just scan randomly; they follow a refined methodology to find hidden bugs that automated scanners miss.

  1. Reconnaissance (The Key): The most important phase. Hunters spend 70% of their time mapping the target's infrastructure, finding forgotten subdomains, hidden API endpoints, and old development servers using tools like Amass, Subfinder, and httpx.
  2. Fingerprinting: Identifying the exact technologies, frameworks, and versions running on the target using tools like Wappalyzer or Nmap.
  3. Vulnerability Discovery: Manually testing for Business Logic Flaws, IDOR (Insecure Direct Object References), XSS, and SQLi. Automated scanners are often blocked by WAFs, so manual testing is required.
  4. Exploitation (PoC): Safely demonstrating the bug without causing actual damage to the system. For example, proving an XSS by popping an alert box with your username.

4. Writing a High-Quality Report

A bug is only as good as the report you write. If the company's security team cannot understand or reproduce your bug, they will close it as "Not Applicable" (N/A) and you won't get paid.

Structure of a Winning Report

  • Title: Clear and concise. (e.g., "Stored XSS in Profile Picture Upload Field via SVG file").
  • Description: Explain what the vulnerability is and where it is located.
  • Steps to Reproduce: Numbered, easy-to-follow steps. (1. Log in, 2. Go to /profile, 3. Upload malicious file...).
  • Proof of Concept (PoC): Screenshots, HTTP requests, or a short video proving the exploit works.
  • Impact: Explain the business risk. (e.g., "An attacker could steal the session cookies of any user who views the profile").
  • Remediation: Suggest how to fix it. (e.g., "Sanitize all SVG uploads and strip executable JavaScript tags").
