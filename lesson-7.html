Network Security: Firewalls & Defense in Depth

Understanding how firewalls protect network perimeters, applying layered security, and mitigating application and network-level attacks.

Introduction to Firewalls

A firewall is a network security device that monitors incoming and outgoing network traffic and decides whether to allow or block specific traffic based on a defined set of security rules. Firewalls act as the first line of defense in network security, establishing a barrier between trusted internal networks and untrusted external networks (such as the Internet).

Firewalls can be implemented as hardware devices, software programs, or a combination of both. Hardware firewalls (like Fortinet, Cisco, or Palo Alto) are physical appliances deployed at the network edge. Software firewalls (like Windows Defender Firewall) are installed directly on individual hosts to control inbound and outbound traffic for that specific machine.

A common firewall architecture involves placing the firewall between the Internet and the Local Area Network (LAN). The firewall blocks malicious traffic from entering the LAN while allowing legitimate traffic to reach internal servers (like Web, Database, and File servers).

Firewall: Packet Filtering

Packet filtering is a fundamental firewall technique that operates at the Network and Transport layers (Layers 3 and 4 of the OSI model). The firewall examines each packet passing through it and checks it against a set of predefined rules. The decision to allow or drop the packet is based on:

  • Source IP Address
  • Destination IP Address
  • Source Port Number
  • Destination Port Number
  • Protocol (TCP, UDP, ICMP)

Access Control Lists (ACL) & Policies

Firewall policies are implemented using Access Control Lists (ACLs). An ACL is a sequential list of rules that the firewall reads from top to bottom. When a packet matches a rule, the firewall executes the specified action (Allow or Deny) and stops reading the rest of the list.

Key Takeaway

When configuring firewall rules, order matters. The firewall evaluates packets sequentially. A common best practice is to place the most specific "Deny" rules at the top, followed by "Allow" rules, and end with a default "Deny All" rule to ensure no unauthorized traffic slips through.

Applying Layered Security (Defense in Depth)

Defense in Depth is a cybersecurity strategy that uses multiple security measures to protect the integrity of information. If one line of defense is compromised, additional layers exist as a backup. This approach acknowledges that no single security mechanism is perfect.

As shown in the diagram, a robust security posture requires controls at every layer:

  • Physical: Locks, biometric access, security cameras to protect hardware.
  • Perimeter: Border routers, external firewalls, DMZs to protect the network edge.
  • Network: Internal firewalls, Network Access Control (NAC), network segmentation.
  • Host: Antivirus, Endpoint Detection and Response (EDR), OS patching.
  • Application: Web Application Firewalls (WAF), secure coding practices, input validation.
  • Data: Encryption at rest and in transit, Data Loss Prevention (DLP) tools.
  • Policies: Security awareness training, Acceptable Use Policies (AUP), incident response plans.

Application Attacks

Application layer attacks target software vulnerabilities to gain unauthorized access, steal data, or disrupt services. Attackers exploit weak input validation, misconfigured servers, or unpatched software. Because these attacks occur at Layer 7 of the OSI model, they can easily bypass traditional packet-filtering firewalls.

Common Application Attack Vectors:

  • Hijack Token / Session ID: Stealing a user's session cookie to impersonate them on a web application.
  • Unpatched OS / Service Misconfiguration: Exploiting known vulnerabilities in the operating system (like IIS or Apache) or taking advantage of default credentials and open ports.
  • Bad Input Checking: Failing to sanitize user input, which can lead to Cross-Site Scripting (XSS) or buffer overflows.
  • SQL Injection (SQLi):strong> Inserting malicious SQL queries into input fields to dump, modify, or delete the backend database.

Network Attacks

Network attacks occur at various layers of the network stack (from the Physical layer up to the Application layer). Understanding where these attacks happen is critical for deploying the correct defensive controls.

Common Network Attack Types:

  • Phishing Attachments / Malicious Code: Delivered via email or malicious websites to compromise the client workstation.
  • Zero-Day Exploit: Attacking a previously unknown software vulnerability before the vendor releases a patch.
  • Distributed Denial of Service (DDoS): Overwhelming a target service with traffic from multiple sources, rendering it unavailable to legitimate users.
  • Man-in-the-Middle (MITM) / Spoofing / Sniffing: Intercepting network communications to steal credentials or alter data in transit.

Authentication Factors (MFA)

Authentication is the process of verifying a user's identity. The strength of authentication depends on the number and type of factors used. Implementing Multi-Factor Authentication (MFA) is one of the most effective ways to prevent unauthorized access, even if passwords are compromised.

The Three Factors of Authentication

MFA requires the user to present two or more of the following independent credentials:

  • Something you know (Knowledge factor): A password, PIN, or security question.
  • Something you have (Possession factor): A smartphone (to receive an SMS code or authenticator app prompt), a smart card, or a hardware token.
  • Something you are (Inherence factor): Biometrics, such as a fingerprint, facial recognition, or retina scan.

Single-Factor Authentication (SFA) relies only on "something you know" (a password), making it highly vulnerable to credential theft. Multi-Factor Authentication (MFA) combines factors, so even if an attacker steals your password, they still cannot access the account without your phone or biometric data.
